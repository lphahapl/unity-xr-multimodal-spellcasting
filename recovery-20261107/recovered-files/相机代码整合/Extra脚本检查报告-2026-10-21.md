# Extra 脚本检查

检查目录：D:/unity_training/Runnner&&Lucy/Assets/Scripts/Extra。此次未修改原工程脚本或场景。

## 阻止正常运行的问题

1. **ChessSlot.cs:11：移动方向写死为世界 +X。** `moveDir = Vector3.right` 不会读取格子的旋转。一个绕 Y 旋转 90 度的格子，实际本地 +X 是 (0,0,-1)，脚本仍得到 (1,0,0)。应取 `transform.right`。如果格子之后还会动态旋转，应用属性读取当前方向，或在需要时刷新。

2. **ChessBoard.cs:14、25：列表顺序与 index 没有建立一致关系。** `GetComponentsInChildren` 的遍历结果不等于路线编号顺序，当前既没有排序，也没有初始化或校验唯一 index。以层级顺序 [2,0,3,1] 为例，调用 index=0 格子的下一格，返回的仍是 index=0。应按明确的路线顺序建立列表，并保证 index 与列表下标相同，或用明确的索引映射查找。

3. **已保存的 BoardDemo 场景配置未完成。** 场景内 ChessBoardContorllor 的 chessBoard、currentChessSlot 均为空，speed=0；Assets 下场景和预制体里未发现挂载 ChessSlot 脚本的组件。按这个保存状态运行会先在 Controller.Start 解引用空棋盘；即使补上引用，空棋盘 MaxNum=0 也无法取模查找。运行时临时设置、未保存的 Inspector 修改不属于本次文件检查结论。

## 移动协程的问题

4. **ChessBoardContorllor.cs:34–35：目标距离不能代表已走步数。** 4 格棋盘从 0 格请求走 4 步，终点仍为 0，协程第一次 MoveNext 就返回 false，实际没有走一格。应使用步数循环控制，按 num 次逐格移动。

5. **ChessBoardContorllor.cs:42–43：currentChessSlot 提前更新。** 启动一次单步移动后，人物距离新格仍有 1m，currentChessSlot 却已经指向新格。应先保存 nextSlot，等待单步完成，再更新当前格。

6. **ChessBoardContorllor.cs:24–28、63–75：缺少运行条件检查。** MoveSteps 没有阻止移动中再次启动协程，没有拒绝非法步数或非正速度。speed=0 的单步协程连续迭代仍不结束、人物保持原位；重复调用会让多个协程同时操作同一个 Transform。speed 也不宜同时承担米/秒移动速度与 Slerp 插值参数的职责。

7. **ChessBoard.cs:14：Inspector 预填列表时会重复收集。** AddRange 不会清除已有元素。列表已经包含 4 个子格时再执行收集，会变成 8 个。应明确采用自动收集还是手动列表，不把两种结果直接叠加。

8. **完成句柄未清空。** isMoving 已在正常结束时设为 false，但 moveCoroutine 仍保存旧句柄，不能用 moveCoroutine != null 判断是否仍在运行。

## 已正确的部分

- MoveTo 使用 yield return StartCoroutine(MoveAStep(...))，会等待单格移动完成。
- 调用 MoveAStep 时只传 speed，Time.deltaTime 只在子协程内乘一次。
- OnArrived 已移到 MoveTo 的结尾，正常完成时序正确。
- MoveAStep 每帧使用 who.position 作为当前位置，最后消除容差。
- ChessBoardCamera 的基准跟随、旋转、平移、遮挡前 0.05m 停靠、遮挡移除恢复、忽略 Trigger 和 LayerMask 过滤用例通过。
