# 棋盘模型 v3：零件轴向统一，碰撞体与模型同节点

## 本次修改

- 每格根节点的本地 +X 指向下一格，本地 +Y 朝上，路线为 00 → 01 → … → 35 → 00。
- 顶面、底座、边条、箭头、问号、金币等 116 个网格零件的本地轴与所属格子保持一致。选择顶面时看到的红色 X 轴也代表前进方向。
- 四角分别按离开该格的方向处理：00、09、18、27。此前 00/18 顶面的 X 轴反向，09/27 顶面的 X 轴与前进方向垂直；本版均已修正。
- 已将零件的旋转与缩放烘焙进网格，保持可见几何位置不变；原有米白格面、彩条和图标外观保留。
- 移除独立的 Route_Colliders 层。每格的 BoxCollider 直接挂在 Geometry/Tile_XX_类型 根节点上，方便代码在碰撞命中时取得格子节点和移动方向。
- 中心面板的 BoxCollider 直接挂在 Center_Panel_Removable 上。
- 目标工程已经原地更新模型、预制体与生成工具，资源 GUID、URP 材质和场景保持原有引用。

## Unity 使用

你的 Runnner&&Lucy 工程使用 URP，导入 ModularBoard_v3-URP.unitypackage。Built-in 项目使用 ModularBoard_v3-BuiltIn.unitypackage。

完整棋盘预制体：Assets/ModularBoard/Prefabs/Board_10m_36Tiles.prefab。

每格模型根节点位于 Geometry 下，例如 Tile_18_Start。可将格子业务脚本挂在这个节点，与 BoxCollider 放在一起。平移方向使用 tileTransform.right（本地 +X 在世界空间中的方向），不是 transform.forward。

生成工具菜单 Tools → Modular Board → Create Prefabs and Materials 会依照当前渲染管线生成材质、预制体与同节点碰撞体。生成工具会更新同名资源。复制到现有工程时只需要 Assets/ModularBoard；Unity 文件夹本身保存 Built-in 验证工程的资源和设置。

## 尺寸与碰撞体

- 每格占地 1m × 1m，转角同尺寸，原点位于底面中心。
- 基础厚度 0.12m，浮雕最高约 0.141m。
- 棋盘总尺寸 10m × 10m，36 格，中心面板 8m × 8m。
- 每格 BoxCollider 的本地 center 为 (0, 0.06, 0)，size 为 (1, 0.12, 1)，覆盖平面行走区域；图标浮雕不单独增加碰撞体。
- 全棋盘共 37 个 BoxCollider：36 格与中心面板。

## 文件

- Blender/ModularBoard_v3.blend：可编辑源模型；场景世界 Z 朝上，格子与其零件的本地 +Y 为表面法线。
- FBX：适配 Unity 的完整棋盘与 9 种独立格子。文件内部已补偿 Unity 导入时的 X 轴镜像，方向以 Unity 中导入结果为准。
- GLB：同一组模型，保留 glTF 右手坐标约定，内含 PBR 材质。
- 预览：原模型的实模渲染，外观保持一致。
- unity-route-layout.json：Unity 中 36 格的实际位置、right、up 和下一格编号。
- board-layout.json：建模、glTF 与 Unity 的坐标数据。
- tile-part-axes-validation.json：36 格与 116 个可选网格零件的轴向检查。

## 验证

Blender 检查与重新导入检查覆盖源模型、FBX、GLB。Unity 2022.3.62f3c1 实际导入并生成预制体，验证每格和全部零件 +X 指向下一格、+Y 朝上、碰撞体位于模型格子根节点。几何顶点相对旧版的最大浮点差异小于 0.000002m。

目标工程资源同步后再次检查全部 36 格与 116 个网格零件，四角均通过，原有 10 个 URP 材质保持不变。详见 unity-validation.txt、geometry-validation.json、export-validation.json、appearance-validation.json 和 project-sync.json。
