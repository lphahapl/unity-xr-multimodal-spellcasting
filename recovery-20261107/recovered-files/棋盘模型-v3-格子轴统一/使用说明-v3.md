# 棋盘模型 v3：零件轴向统一，碰撞体与模型同节点

每格根节点的本地 +X 指向下一格，本地 +Y 朝上，路线为 00 → 01 → … → 35 → 00。顶面、底座、边条和图标等全部 116 个网格零件也采用相同的本地轴，选择顶面时看到的红色 X 轴同样代表前进方向。

四角 00、09、18、27 已分别验证。此前 00/18 顶面的 X 轴反向，09/27 顶面的 X 轴与前进方向垂直；本版将旋转烘焙进网格，保留原来的几何外观，统一零件轴向。

## 碰撞体与模型

已移除独立的 Route_Colliders 层。每格 BoxCollider 直接挂在 Geometry/Tile_XX_类型 根节点上，中心面板的 BoxCollider 挂在 Center_Panel_Removable 自身。

建议将格子业务脚本与 BoxCollider 一起挂在 Tile_XX_类型 上。代码使用 tileTransform.right 获取世界空间前进方向；transform.forward 是本地 +Z。

每格 BoxCollider 的本地 center 为 (0, 0.06, 0)，size 为 (1, 0.12, 1)。全棋盘共 37 个 BoxCollider：36 格和中心面板。图标浮雕不单独添加碰撞体。

## 导入

Runnner&&Lucy 使用 URP，导入 ModularBoard_v3-URP.unitypackage。Built-in 项目使用 ModularBoard_v3-BuiltIn.unitypackage。

完整棋盘预制体为 Assets/ModularBoard/Prefabs/Board_10m_36Tiles.prefab。已有目标工程已就地更新 Models、Prefabs、Editor，资源 GUID、URP 材质与场景引用保持原有配置。

生成工具菜单 Tools → Modular Board → Create Prefabs and Materials 会依据当前渲染管线创建材质、预制体与同节点碰撞体，更新同名生成资源。Unity 文件夹保存 Built-in 验证工程的资源和设置。

## 尺寸与文件

- 单格占地 1m × 1m，转角同尺寸，原点位于底面中心。
- 基础厚度 0.12m，浮雕最高约 0.141m。
- 棋盘 10m × 10m，36 格，中心面板 8m × 8m。
- Blender/ModularBoard_v3.blend 为可编辑源模型。Blender 世界 Z 朝上，格子本地 +Y 为表面法线。
- FBX 文件补偿 Unity 导入时的 X 轴镜像，方向以 Unity 导入结果为准；GLB 保留 glTF 右手坐标约定。
- 模型内含纯色材质，无外部贴图依赖。Blender 源文件中各零件已使用独立网格以烘焙各自的朝向。
- unity-route-layout.json 保存 Unity 中各格的位置、right、up 与下一格编号。
- board-layout.json 保存建模、glTF 与 Unity 的坐标数据。

## 验证

Blender 检查、FBX / GLB 重新导入检查及 Unity 2022.3.62f3c1 实际导入均通过。逐格验证了根节点、116 个网格零件的 +X / +Y、尺寸及同节点碰撞体。模型顶点相对旧版的最大浮点差异小于 0.000002m。

同步后再次检查目标工程资源，四角及全部零件均通过，10 个原有 URP 材质保持不变。验证记录为 unity-validation.txt、tile-part-axes-validation.json、geometry-validation.json、export-validation.json、appearance-validation.json 和 project-sync.json。
