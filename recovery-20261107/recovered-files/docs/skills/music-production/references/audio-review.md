# 音频复查

## 分开记录三种证据

| 层次 | 能验证什么 | 不能据此宣称什么 |
|---|---|---|
| 乐谱/事件 | 音符、音区、主题变化、声部占用、预期和声 | 实录源没有杂音、成品一定和谐 |
| 波形/频谱 | 格式、电平、起音、音高族、包络、接缝异常 | 有叙事感、音色自然、久听不疲劳 |
| 真实试听 | 音色、呼吸、层次、情绪、循环感、实际使用效果 | 未测试设备或场景同样通过 |

没有音频理解或实际听音能力时，仍完成可用的乐谱/数值检查，明确留下试听项。播放工具或生成音频文件不等于已经听过。

## 音源先于整曲

记录作者/库、授权与署名要求、来源链接、文件哈希、源格式、切片范围、实测根音和处理链。公开可下载不自动等于可发布；MP3试听源不标成无损母带，实录、合成和替代乐器按实际说明。

对实际使用的根音和目标音区取样检查：

1. 核实基频与八度映射，文件名的八度命名可能不同。调音参数的正负与重采样方向必须实测。
2. 分别看起音、主体与尾音，区分另一声部、再次拨弦、背景噪声、自然颤音和弦的非整数泛音。候选切点元数据未必包含所有后续起音。
3. 结合多个时间窗与谐波族判断串音；立体声分析保留两声道或平均功率，避免单声道相消造成误判。单个旁峰不自动代表另一个音。
4. 源不合适时，先换更干净的演奏、缩短受污染部分或撤去不必要补奏。已确认的局部余音可尝试有限窄带减弱，比较目标泛音与起音是否保留。大量谐波重建、宽频去除或拉伸可能改变音色，不能只追求更“干净”的频谱。
5. 某个来源确认有问题后，按源映射查找整首所有使用位置，包括移调后音符和循环边界；保留受影响事件清单。

## 从实际发声检查重叠

把起音延迟、延音/松键、采样自然尾部及效果尾部计入占用，不只看MIDI note-off。分别检查同一主奏前后音、主奏与伴奏、相邻句、跨循环事件。吹奏换气与演奏法按风格决定；没有统一适用于所有音乐的40ms间隔。

先检查分轨，再检查完整混音。弱背景经过音与突出的低区二度簇影响不同；确认严重性时包含时间、音高、持续时长、相对电平和音乐功能，不能把“消除全部二度”作为质量目标。

## 只读分析脚本

依赖 Python、NumPy、SciPy、SoundFile、pyloudnorm。先检查现有运行时；脚本不会联网、安装依赖或修改原音频。下例路径以执行时的真实文件替换，输出必须是新文件：

```powershell
python -X utf8 <skill目录>/scripts/analyze_audio.py <音频路径> --out <新报告.json>
python -X utf8 <skill目录>/scripts/analyze_audio.py <音频路径> --out <新循环报告.json> --loop --sections <段落.json> --window-seconds 4
```

可选段落文件格式（单位秒，边界应在实际音频内）：

```json
{
  "sections": [
    {"name": "引子", "start": 0, "end": 8},
    {"name": "主题", "start": 8, "end": 24}
  ]
}
```

报告包含输入哈希与格式、峰值、RMS、LUFS、4倍过采样峰值估计、等长窗口及指定段落。`--loop`才增加首尾差值与局部变化比较。短于响度测量窗口或静音时，LUFS可能不可用，以`null`及说明表示。跨版本比较使用对应音乐段落，时长变化后不要机械比较同一秒数。

解释时区分：dBFS峰值、dBFS RMS、LUFS综合响度和LU响度差；分轨能量比例不是听觉占比。过采样峰值是工程估计，不冒充认证的真峰值仪表。等长窗口的极差不是标准LRA，稀疏休止会放大它。

波形边界小于局部差分分位只说明未见突出的样本跳变；首尾为零、过零点或加淡变也不能证明音乐和播放器无缝。脚本不输出“好听/和谐/循环通过”的自动判决。

## 收尾尺度

检查整个成品，重点回看首段、最密处、最弱处、所有修改处与连接段。分轨/全曲的参数和起点要一致，确认最终发布文件与验收文件哈希对应。保留一份简短报告：需求覆盖、已发现及修正问题、数值结果、实际试听方式和未解决项；不编造综合“自然度分数”。
