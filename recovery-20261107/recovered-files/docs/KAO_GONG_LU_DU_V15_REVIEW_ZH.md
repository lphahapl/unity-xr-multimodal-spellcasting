## 一、整体判断

**创意方向比上一轮更成熟，可以继续收敛；V1.5 的技术映射仍有确定错误，暂不适合直接交给程序照表执行。**

值得保留的内容：

- “天地是一架脱扣的大钟，工匠修补其规矩”比大量现代物理公式更容易形成画面，也能串联场景异常、器物、敌人和修复目标。
- 准望匣、铜叶、墨规笔属于同一套工艺语言，有利于第一人称辨识和模块化美术。
- 画符被定位为修补机关、战前备战，且与战斗输入互斥，玩法身份比“额外再加一种攻击手势”更明确。
- 负衡偶的“重兵器卡地后暴露核心”有可读的因果关系，可以先用简单机关演示，不必一开始制作完整角色。

新功能没有实现并不代表创意不合理。需要修正的是：**把新增设计写成现有能力、把局部比喻写成普适物理、把未经验证的效果写成保证。**

## 三、确定的技术与玩法冲突

### T-01｜Boss 教学要求“持核闪避”，与右手输入归属冲突

**定位**：V1.5 §7，第 124 行；白皮书幕五，第 252～254 行。

当前流程要求提前握好火核，再右手平切躲开重砸，接着立即投核。

**实际行为**：`LinearRpgController.cs:387` 将右手持有投掷物标记为 `rightMotionOwnedBySpell`。`RpgGestureState.cs:109` 的归属恢复逻辑在该标记有效时不恢复闪避识别；`LinearRpgController.cs:217` 的模拟入口也明确拒绝持投掷物闪避。这是防止同一挥手同时发射和位移的现有约束。

**后果**：按文档提示提前持核的玩家，恰好无法使用下一步要求的右手闪避。

**建议**：首版改为“空手闪避 → Boss 卡地 → 结印、念咒、生成、瞄准并发射”。9～10 秒弱点时间是否足够，要用新手实测决定。也可研究持核时用左手合法节点位移躲避，但必须明确其操作、可用节点及输入仲裁，不能直接当作右手闪避已经成立。

**请答复**：采用现有输入约束调整教学，还是正式提出修改持核与闪避仲裁的需求？

### T-02｜火核当前由头显朝向瞄准，手臂动作负责触发发射

**定位**：V1.5 §2、§3；白皮书 §5.3、§6.2 的“沿手臂加速度与惯性”“单眼瞄准”等叙述。

最新 `docs/FIREBALL_TUNING_ZH.md:59` 与 `SkillEffects.cs:394`、`:535`、`:567` 的行为是：头显正前方射线选择目标点，火球从手中出手位置飞向该点，并检查遮挡。松手投掷、后拉前送、伸手保持是三条发射触发路径；动作速度不决定飞行速度，当前火球配置速度为 9 米/秒。

“单眼瞄准”也不等于工程具有眼动追踪；这里取的是头显朝向。

**建议文案**：“准望匣依视向定轨，工匠以送势解缚出手。”保留投掷的身体感，同时准确表达目标选择。三种动作可以共用这一解释，不要求所有玩家大幅甩手。

**资料更新说明**：上一轮问题单对手部轨迹决定方向的描述已经过时，本条覆盖该部分，不要求 Gemini 为尚未收到的更新负责。

### T-03｜四阶段可以作为教学结构，不能规定全技能都结印念咒、托掌持有

**定位**：V1.5 §3，第 60～75 行；白皮书 §6.2。

`SkillDefinition.cs:6` 明确包含纯手势、纯口令、口令与手势组合。纯口令不需要结印，纯手势不需要念咒；护盾激活后直接生效，不需要经过持物与出手过程。雷剑、牵引等还是规划，不能反过来证明所有效果都适用“法宝托掌在手”。

**建议**：保留“准备 → 输入配方 → 成立 → 效果运行”四个面向玩家的概念。输入配方按模式展开，效果运行按投射物、护盾、未来工具分支。先说后结印与先结印后说都成立；8 秒是默认匹配窗口，不是固定吟唱或蓄力时长。

“1 帧内自动进入运法”应移出世界观。实现验收应关注激活是否成功、资源是否正确提交、失败是否恢复，而非把某种帧数写成法理。

### T-04｜抬腕、点击菜单、卡片可见、画符独占是不同状态

**定位**：V1.5 §4，第 85 行；白皮书 §3.1，第 84 行。

当前默认入口是 `WristMenuActivation.TapWrist`，`requireWristFacing` 默认关闭。玩家抬左腕后，由右指主动点腕饰；单纯抬腕面向头显不自动占用输入。显式操作意图和后续 UI 状态参与仲裁。

独立卡也有各自策略：结印卡、咒语卡默认放腕保留，画符预览默认随腕关闭。卡片留在世界里不等于永久阻止战斗。当前子面板使用射线高亮后捏下确认，并有松开重备；画符独占则属于后续设计。

**证据**：`WristMenuState.cs:6`、`:21`、`:40`，`WristMenuController.cs:17`、`:134`、`:191`。

**建议**：保留铜叶自动收纳的器物动画，但明确收回的是入口支架，已经调出的独立速查卡依其策略保留。不要用一条“放腕全部收起”替代交互规则。

### T-05｜当前火球撞墙结束；反弹不是已具备的底层物理

**定位**：V1.5 §4，第 81 行；白皮书 §5.3。

`SkillProjectile.cs:93` 的 `Hit()` 在首次有效命中时锁定结束状态，结算目标、生成视觉、清理对象，没有反弹分支。把矩印镜接进现有场景不会自动获得绕掩体弹射。

白皮书还混用了“入射角等于反射角”和“完美直角反射”：一般反射并不保证方向转过 90°。如果镜子总把火核转成直角，应说明是机关主动改轨。

**建议**：首片保留直线命中；矩印镜标为新增机制。若要做，补反射面规则、反弹次数、能量/寿命处理、接触偏移避免连撞、预测线和伤害去重。普通墙面与专用镜面必须区分。

### T-06｜度力恢复和护盾承伤描述不准确

**定位**：V1.5 §1.1、§2、§4；白皮书 §2.3。

- 当前火球消耗 20 MP，默认上限 100；不考虑恢复时支持五次消耗，不是固定“四核耗尽”。实际可用次数还受恢复、冷却和手槽影响。
- `RpgPlayerState.cs:37`、`:91` 表示成功消耗后等待 2 秒再按配置恢复；没有停步、深呼吸或脱战判定。默认每秒 5 点，从 0 到 100 需要恢复 20 秒，另加恢复等待，不能写成“调息两秒即迅速盈满”。
- `SkillEffects.cs:676` 按剩余护盾值吸收，超出部分继续伤害玩家；护盾也有持续时间到期路径。不能笼统承诺全额吸收直到碎裂。

**建议**：“度力在短暂回息后逐渐恢复；定规障在存续期间抵消有限伤害。”停步加速恢复可保留为新提案，但需单列实现与平衡成本。

### T-07｜徒手路线没有手柄接触，震动服务不能提供掌心触觉

**定位**：V1.5 §11，第 166 行。

当前核心玩法是放下控制器、追踪裸手。给 XR 手柄发送震动，不会让玩家的手掌获得点腕、持核或格挡触感。接口存在也不意味着硬件具备输出能力。

**建议**：当前版本以声音、指示动画和效果形变反馈为主。手柄或触觉外设支持列为可选适配，注明目标设备及佩戴方式；从徒手必需的 P1 清单中移出，除非项目决定改变硬件范围。

### T-08｜Ducking 是待实现的降噪措施，不能保证 KWS 命中率超过 95%

**定位**：V1.5 §9，第 143 行；§11 音频管理器。

在本次检索的 `Assets/SealCombat` 与 `Tools/SkillVoice` 源码范围内，未找到文档所述 VAD 驱动的游戏音量衰减实现。现有关键词接收事件不能直接充当提前发现说话意图的 VAD。

即使实现音量衰减，也要验证触发延迟、自己播放的语音触发、外部声音、串流麦克风及漏检/误报。背景音量降低不能据此推导固定识别率，更不能解决否定句包含关键词的问题。

**建议**：把 -8 dB、1.2 秒写成试验参数；以多人、多环境的命中率、误触发次数/小时和延迟统计验收。衰减脚步声还可能掩盖 Boss 攻击提示，需要保留关键战斗声或同步视觉提示。

### T-09｜首片依赖尚未排进首片的功能，性能与工期保证也过满

**定位**：V1.5 §8、第 130～134 行与 §11。

首片流程包含跨深渊长距移动、画符开门、三只敌人和完整 Boss；优先级表却把画符放 P2、长距移动放 P3，并明确暂缓 Boss。当前节点位移可以复用，但“超远距离探索缩地”和已有节点导航是否同一功能，需要先定义。

其他需要纠正的工程表述：

| 原说法 | 问题与建议 |
|---|---|
| Unity 2022.3 LTS | `ProjectSettings/ProjectVersion.txt` 当前为 6000.3.10f1，应同步 |
| 0.65 秒滑移 | 当前射线驻留为 0.32 秒，旧方向驻留为 0.65 秒；`MoveToNode()` 验证后直接平移 Rig，不是沿路径滑行 0.65 秒 |
| 对象池配合 MPB 确保 SRP Batcher，彻底消灭 GC 掉帧 | 池化不自动证明渲染兼容或全部零分配；当前投射物仍使用 `SphereCastAll`、`OverlapSphere` 等返回数组的查询。应分别测分配、CPU/GPU 时间、批处理路径，而不是保证结果 |
| 定目帘是 50 行极简组件，保玩家不眩 | 代码行数不能代替双目渲染、遮罩表现、过渡与可配置性验收，也不能保证每位玩家舒适 |
| Cinemachine 运镜 | 不应据此强制移动或旋转玩家 HMD；优先用于独立观众镜头，第一人称叙事尽量让玩家保留头部控制 |
| 小怪必须先做行为树 | 先定义待机、预警、攻击、受击、死亡等行为即可；采用状态机还是行为树应由实际复杂度决定 |

**建议交付两个范围**：A 为现有技能、节点与静态机关的可玩闭环；B 为加入画符、小怪、Boss 的展示目标。写清 B 的前置条件，不让 A 的验收依赖 B。

## 四、世界观与系统设计需要回答的问题

### W-01｜方圆界的移动规则与定目帘触发原因没有闭合

**定位**：白皮书 §3.2～§3.3；V1.5 §1.1、§2。

目前方圆界既像以双足为中心随身移动的领域，又像固定在起点的保护区；半径约 2～3 米，但 0.8 米闪避又被定义成冲出领域。如果领域随身移动，为什么离界？如果领域固定，为什么近距离一步就出界？

更大的问题是：界外若会瞬间撕碎凡人，定目帘只能遮光，如何保护身体？攻击从混乱区进入界内，是仅恢复正常轨迹，还是会被结界挡下？若会挡下，为何还需要定规障？

**可选修订方向**：方圆界是随身维持的局部稳定层，位移时短暂重新锚定；定目帘只遮挡重锚时的视觉扰动，不承担防伤。方圆界维持环境常态，定规障抵抗外来冲击，两者职责不同。此为建议，待项目所有者选择。

若不准备开发真实的区域物理变化，也应说明这是场景演出和器物叙事，不意味着运行时逐物体切换重力与空间规则。

### W-02｜战前冷铸拓片有无限囤积和即时解围的漏洞

**定位**：白皮书 §4.4；V1.5 §1.2、§5。

如果仅消耗会自动恢复的度力，玩家是否可以在安全区反复画符，无限制作保命拓片？使用时捏碎又如何区别于持火核握持、UI 轻捏、结印？危急时从哪里取，是否占用手槽，能否在持核时使用？

还需明确：拓片是格挡一次伤害，还是三秒无敌；是否与定规障共享容量；死亡和读档后数量如何处理；进入画符模式时已有火核、护盾、飞行效果和待匹配口令如何处理。

**建议首版**：画符先只用于安全区机关修复。消耗品另列后续需求；若必须保留，可先研究单格预备槽、有限材料或不可叠加规则，不能默认免费恢复资源足以约束囤积。

### W-03｜“修补缺口”与“识别一个完整圆”是两种不同任务

**定位**：V1.5 §5.2；白皮书 §4.4、幕三。

故事说补齐已有图案缺失的四分之一圆，程序说明却是把玩家轨迹当完整圆/方进行模板匹配。如果输入只有缺口的一小段，完整圆模板可能不匹配；如果只看归一化点云，又未检查位置与方向，可能在画板任意角落画圆也能开门。

**请明确选择**：自由画完整规印，还是在固定机关图上补线。后者需判断起止区域、缺口覆盖、允许越界、完成时机和错误恢复。32 点重采样或采用某个算法都不能代替这些关卡判定。

另一个交接差异：白皮书写“必须插回侧套”才能退出，V1.5 写“收起或松开笔”退出。要统一主动退出、松手、追踪丢失与安全恢复，不能把追踪中断当作完成画符。

### W-04｜末世日常、玩家动机和力量边界需要恢复到新版中

**定位**：白皮书第一、二卷；V1.5 §1。

1. **灾难持续三千年，凡人如何活到今天？** 如果界外普遍立即致死，人类聚落、食物、工具与传承靠什么维持？可以设稳定地带、旧基标庇护区或局部异常，而非所有地点都持续极端失序。
2. **沈商此刻修这一座废阁，为谁、为了什么？** “最后的勘律使”是身份，不是具体行动动机。首片修复后最好有一件可见的改变，例如恢复聚落供水、稳定通路或取得下一处基标位置。
3. **主角修什么，不能修什么？** 能补巨门零件，为什么不能随手修复敌人、铸无限武器或直接重建天钟？桌面 V1.4 的模具、作用尺度、生体限制等规则值得保留，避免新版删去后力量再次无限扩张。
4. **七正度与声律、度力各是什么层级？** 新版七正度中没有“律”，但唱诵依然承担激活；度力又兼作身体资源。可用一张短表说明“世界运行基准 / 操作媒介 / 个人消耗”，不必再造一组公式。

这些是设定待补，并不要求按现实科学解释空间折叠。建议把“完全遵循生活常识物理”改为“以工匠工具和日常经验构造可读的幻想规则”。重兵器挥空卡地可以成立为设计，不必声称杠杆自动放大惯性几十倍。

白皮书开头的古籍引文还应在对外发布前逐条核验出处与原句。本轮未做古籍考证，不将它们判定为已核实或伪引；无法核实的可改成世界内的工匠训诫，避免混作真实引用。

## 五、建议 Gemini 下一次交付的内容
