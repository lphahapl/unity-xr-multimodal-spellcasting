## 候选与边界

三栏共用 T-21 原网格、贴图和同一 Nib 轨迹。

| 版本 | 可见形变 | 结论 |
|---|---|---|
| A 原版 | 无 | 保留刚性基线 |
| B 落点约束 | 锋根和接触尖端不动，仅笔锋中段沿切向速度反向拖弯 | 推荐进入下一轮审阅；并非用户已选定 |
| C 自由锋尖 | 从锋根到尖端逐渐增加拖弯，逻辑 Nib 仍不动 | 反向摆动更直观，但可见尖端和落墨位置错开；作为问题对照保留 |

两种形变都不修改逻辑采样锚。B 比 C 多约束了可见接触尖端。若需要尖端本身明显反向甩动，应先决定是否接受笔尖与墨迹分离，不能在表现代码里暗改识别点。

## 计算方式

- 以接触板局部 XY 的连续 Nib 位移计算相对切向速度，忽略法向 Z。世界空间的板转向应先还原到板局部；不要从稀疏墨迹点估速度。
- 反向目标位移为 `-v * gain`，限幅后指数平滑；停笔、抬笔和失追回零。换板、首帧、长帧间隙、倒退时间或重接触重建差分基线。
- 预览采用 gain=0.08 秒、最大 4.5 mm、跟随时间常数 45 ms、回正时间常数 60 ms、速度死区 5 mm/s。计算核默认 gain=0.018 秒；预览明确覆盖该值以便看清候选。均为样板参数。
- 只作用于原模型本地 Z=0.0677 到 0.108 米之间的笔锋。B 权重为 `sin²(πt)`；根和尖固定。C 对照权重为 `t²`。铜箍、笔杆、握点完全不参与。
- 实际浏览器样板为独立 CPU 顶点形变，每次从原顶点计算，不累计形变。没有把这条路径直接安装到 Unity。

## 后续 Unity 接入约束

当前真实链路为 `GlyphPenController.Observe → ConstrainToBoard → context.tip = nib.position → Advance → GlyphBoard.Sample`。先保持这条链路不变，另给表现层只读的板变换、观测时间、Nib 点、有效追踪和书写接触状态。`drawing`、`touchingSurface` 和 `context` 当前是私有状态；正式接线需由负责该控制器的会话协调。板底撤销/清空按钮也可能触发接触，表现层必须排除按钮区域。

Nib 是根节点直属子物体，局部位置 (0,0,0.108) 米，+Z 指向书写方向。可变形的是同级 BrushVisual 中的笔锋，不能移动 penRoot、Nib、采样点、握点、吸附/碰撞包络或画板。共享模型的 FBX `isReadable: 0`，不能直接照搬浏览器 CPU 路径访问 Unity 网格。候选接入可考虑顶点 shader + MaterialPropertyBlock，需验证 URP 法线、边界盒、LOD0/1 和阴影；本轮未实现这一接入。
