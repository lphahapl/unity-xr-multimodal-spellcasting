## 工具选择

首选试验 sherpa-onnx 的中文自定义关键词检测（KWS）。它通过限定关键词解码器检测指定短句，支持自定义关键词而不需要为每个新关键词重新训练。每关键词可设置 boosting score 与 trigger threshold，两者都影响漏检/误触；数值不能直接当作正确概率。

- [sherpa-onnx 官方仓库](https://github.com/k2-fsa/sherpa-onnx)：离线推理，支持 Windows、Android arm64、C#。
- [官方 KWS 说明](https://k2-fsa.github.io/sherpa/onnx/kws/index.html)：自定义关键词与触发参数。
- [官方预训练 KWS 模型](https://k2-fsa.github.io/sherpa/onnx/kws/pretrained_models/index.html)：提供中文 WenetSpeech 3.3M 及中英双语 3M 模型；支持配置拼音关键词。
- [Unity 社区接入工程](https://github.com/xue-fei/sherpa-onnx-unity)：README 列出中文 KWS 模型，记载 Android 构建成功。工程基于 Unity 2021，不能据此宣称本项目 Unity 6 / Quest 已验证可用。
- [官方 C# 麦克风关键词示例](https://github.com/k2-fsa/sherpa-onnx/blob/master/dotnet-examples/keyword-spotting-from-microphone/Program.cs)：可参考接口与流式送音频，不能原样当作 Unity 麦克风模块。

备选：

- [Vosk 官方 Unity 工程](https://github.com/alphacep/vosk-unity-asr)，配 [中文小模型](https://alphacephei.com/vosk/models)。这是 ASR 转文字，中文小模型 42 MB，官方标注适用 Android。固定词表/语法需核对模型词表与动态识别图支持，不能保证任意动漫术名填入就能用；参见 [官方适配说明](https://alphacephei.com/vosk/adaptation)。
- [whisper.unity](https://github.com/Macoron/whisper.unity)：有 UPM 接入、Android ARM64 支持及本地多语言识别。适合通用语音转文字备选；仅几个实时口令时优先验证 KWS。不能把 PC/Mac 演示性能推算到 Quest。

若要求玩家先录几遍自己的咒语、之后按声音相似度匹配，属于另一条路线：VAD 切段 → 特征归一化 → MFCC / 声学嵌入 → DTW 时间对齐 → 距离阈值与第二候选分差。参考 [MFCC+DTW 示例](https://github.com/a37950456/Implementation-of-Dynamic-Time-Warping-DTW-) 仅为算法学习入口，不是成熟 Unity/Quest 插件。需多模板、陌生声音/错误咒语负样本和不同语速测试；直接比较波形或拿动漫原声当玩家声纹模板不适合作为起点。

## 建议的联合判定

保留现有骨骼特征和各印原始得分；在上层增加技能配置和一次施法的状态机。语音和手势各自产生带采集时间的事件，再在同一施法窗口中组合。不要直接把未校准的语音分与手势分加权平均，让一方高分补掉另一方完全错误。

1. 识别到完整、区分度足够的技能短句，建立该技能的候选施法。共有前缀如“领域展开”只用于准备，不立即决定具体技能。
2. 在有限窗口内匹配该技能配置的手势步骤。可允许先做手再开口、边说边做；保留短时手势分数历史，语音确认后按采集时间回看并重新判断，不能只依赖此前严格阈值下已经发出的 Recognized 事件。
3. 每步仍要求有效追踪、覆盖率、最短保持、与竞争印的分差。低阈值只对当前施法候选有效，不回写全局 SO，也不凭空补全无追踪数据。
4. 达到本技能要求的 K 个步骤，且关键收尾步骤完成后，消费语音与手势事件，释放一次并进入冷却。持续保持同一印不能累计多次；重复印需明确离开再进入。

用于试验的自定义规则示例，不代表原作结印：子→丑→寅。

| 模式 | 步数要求 | 子最低分 | 丑最低分 | 寅最低分 |
|---|---|---:|---:|---:|
| 纯手势（如果技能允许） | 完整3步 | 75 | 80 | 80 |
| 对应咒语已确认 | 按顺序完成2步，必须含寅收尾 | 70 | 75 | 75 |

这些是待调参数，不是实测最优值。只喊对咒语不释放，只做无关手势不释放。若需要必须语音的技能，禁用纯手势模式。

首版建议固定语音减免5分，并配置每印最低下限；不要立即按“语音置信度越高/已完成印越多”无限降低门槛。后续可为每技能单独配置减少步数或降低阈值的幅度，避免同时过度放宽。

初始时间窗口可试语音实际说话结束前1秒至结束后4秒，并设整个施法的总时长上限；实际边界需基于说话时长与实测延迟调整。使用音频采集/关键词时间戳对齐 Unity 单调时钟，不能拿推理返回时刻假装玩家刚开口。超时后清除这次施法上下文。

## 可视化与调试

显示：当前短句、语音待确认/已确认、目标技能、各印原始分与本次有效阈值、已完成步骤、追踪覆盖率、窗口剩余时间、拒绝原因。日志区分语音不符、手势不符、分数不足、步骤不足、缺收尾、印歧义、超时。

测试至少覆盖：正确咒语+正确手势、正确咒语+错误手势、错误咒语+正确手势、静音、闲聊、游戏自己的语音回放、快速重复说话和同一印长时间保持。记录漏触、误触、端到端延迟以及 Quest 帧时间。

当前走 Steam Link 时 Unity 实际运行在 PC，先使用头显映射到 Windows 的麦克风，在 PC 本地推理；将来 Quest 原生包再验证 Android arm64 原生库、IL2CPP、麦克风采样和功耗。模型不需要强制移植到 Sentis，可用语音库自身推理后端。

建议第一轮只用2个技能、每技能1句完整中文口令、1个核心手势。完成输入验证后再扩展到2/3步骤与语音阈值减免，避免多个未知条件叠在一起。

### 当前可复用的部分与接口缺口

| 当前文件/接口 | 已有能力 | 施法接入要求 |
|---|---|---|
| `SealLab.cs` / `Frame`、`Features`、`Scores` | 快照、全部印的原始分数、双手新鲜度与同步检查 | 在采样评分完成后发布独立观测快照；不能让消费者长期持有下一帧会清空的 List |
| `SealProfile.cs` / `SealScorer.Evaluate` | 加权匹配、覆盖率、逐特征扣分 | 分离证据计算和通过策略；显式输出模板有效、必需项缺失等标志，不靠解析 reason 字符串 |
| `SealRecognizer.cs` | 单印候选、连续保持、达标候选间分差 | 不承担技能步骤或释放；联合模式独立执行本次阈值策略及竞争印检查 |
| `SealLab.WhenSealRecognized` | 识别结果从非该印变成该印时发事件 | 无事件 ID/时间戳；低于原阈值没有事件；短暂拒绝后恢复会再发。因此不能直接绑定发射或步骤自增 |
| `HandSnapshot.cs` | 关节、有效性、版本和观测时间 | 可用手腕做释放动作；关节处于 recordingOrigin 局部坐标，世界坐标需转换 |
| `SealRecognitionTest.cs` | 运行时模板副本、三块中文面板、失败诊断 | 仅作调试参考；新场景避免同时挂两个修改 lab.profiles 的配置组件 |
| `SealTestDiagnostics.cs` | 特征扣分解释 | 增加本次有效阈值与施法阶段原因，不能只显示全局阈值 |

当前 `required` 只表示特征必须有有效数据，不表示该特征必须达到某个匹配分。若未来需要“关键特征硬门槛”，须增加独立字段，不能误用这个开关。

### 玩家操作流程

默认在训练/战斗模式监听咒语，菜单和录制模式禁用施法。短句和结印允许同步进行，不要求玩家先按按钮。短句锁定技能，印步骤满足后进入就绪并给出短提示音、手边聚能效果和瞄准预览。就绪后可松开复杂的结印姿态，不要求保持全部手指评分，释放动作只检查其真正需要的关节。

| 技能类型 | 第一版释放方式 | 瞄准与效果 |
|---|---|---|
| 投射类：训练能量弹 | 就绪后双手轻推，主要测双腕中心向前位移 | 头部朝向射线给出瞄准点；从双腕中心发射到该点，提交时冻结发射姿态 |
| 自身范围类：训练领域 | 咒语与核心印通过后继续有效保持约 0.4 秒；此模式仍要求该印达标 | 以玩家脚下估计位置/有效地面点为中心，预览半径后展开；不依赖手指指向 |
| 地面指定类（后续） | 就绪后轻推确认 | 头向射线寻找有效地面，落点标记；无有效地面不提交 |
| 持续束流（后续） | 就绪后开始动作，再维持简化姿态 | 另设持续/停止状态与持续耗能，不能当成每帧重新释放 |

头向瞄准指头显相机朝向，不假设眼动追踪。先使用显式绑定的 XR 相机。准星与半径应让玩家在提交前知道技能会去哪里。火影/咒术的区别主要由技能配置和效果表达；不必为两套题材分别做识别器。

### 状态与时序

`空闲 → 收集咒语/印证据 → 技能就绪 → 提交一次释放 → 冷却 → 空闲`。

- 只有独特的完整技能短句才能选技能；共享前缀只显示听取状态。首版一次仅维护一个候选，不因后续碎片文本悄悄换技能。
- 收集阶段允许先印后语音；历史缓存按音频采集时间对齐，保存完整印分数与质量，不能只保存 Recognized 结果。缓存期限必须覆盖允许的前置动作、短句时长和识别延迟预算；过迟结果明确拒绝。
- 步骤是有序索引，不是“任意几个印”。例如 2/3 步且寅必须收尾时，明确允许 `[子,寅]`、`[丑,寅]`、`[子,丑,寅]`，不允许倒序或一个印计两次。
- 同一个印持续保持只有一个进入事件。重复印需在有效追踪下真正离开并重新进入；追踪丢失、歧义和低质量帧不能充当“离开”。每个事件只能由本次施法消费一次。
- 就绪后新建立释放动作基线，**不回放就绪前的推手来自动开火**。预备动作与释放动作分开计时。
- 就绪初始有效期可试 3 秒；到期、明确“取消施法”口令、退出战斗或应用失焦取消。取消后需要新咒语，不能被旧回调重新激活。
- 短暂追踪中断暂停动作判定、重置速度/位移基线；超过试验值 0.25 秒取消就绪。不能把中断后的坐标跳变当推手。计时器由会话自己的每帧 Tick 驱动，不能依赖还有新手部帧到来。
- 释放时检查资源、冷却、姿态有效性和该技能的目标要求，原子地扣资源并生成一次 CastCommand。技能执行按 castId 去重，界面重绘和重复回调不能重复扣资源/生成效果。

以上时间、距离是起步试验值，未经过头显测量，不是保证指标。

### 推手如何检测

使用双腕中心而非遮挡指尖。就绪后先得到短暂稳定的有效腕部样本，再记录中心、头部位置和当时的前方向。建议先试 0.15～0.6 秒内向前约 0.12 米；不要求很高速度。该窗口是一次动作的时长，总等待仍受就绪期限限制。

用锁定的前方向比较手相对头部的前伸量，同时验证手在连续世界坐标下也确实向前移动，以减少仅移动身体、后仰或转头造成的触发。重新定位、传送和 tracking origin 不连续时取消并重建基线。速度用有效样本时间差计算，重复版本不提供新的动作证据。前伸阈值、侧偏容差和动作时限需要测试并可在 Inspector 调整。

手部进入就绪后不再要求原来双手缠绕的指形保持不变；推手阶段仍要求双腕有效、新鲜和时间同步。这是按阶段改变必要数据条件，不是让丢失数据也通过。

### 阈值与事件契约

`有效阈值 = max(本印最低下限, 基础阈值 - 本技能语音减免)`，只对本次候选技能中的步骤生效。保持当前子印 75 分基础配置及禁用中指的决定；例如减免 5 分后 70 分仅是待测试方案。覆盖率、数据质量、步骤顺序、保持时间不随语音自动下降。

联合模式比较目标印与其他有效已标定印的原始分数，不能因为只加载了目标模板就消除歧义；现有识别器只比较两个“已达标”候选，联合模式需要独立的竞争策略。初期可要求目标领先竞争印 5 分，记录因此漏过的样本后再决定是否放宽。只有三个模板时，只能评估三类之间的混淆，仍须加入自然手势负样本测试。

建议新增下列数据契约，而非把 Recognized 直接连到 Instantiate：

- `SealObservation`：sampleId、采样时间、左右观测时间与版本、有效性、全部印的分数/覆盖率/缺失标志，以及必要的手腕姿态。为不可变副本；必要时回指可回放骨骼记录。
- `VoiceIntent`：utteranceId、skillId、采集起止时间、返回时间、确认状态、检测器原始值。原始值不称概率；音频线程通过队列进入主线程。回调携带 sessionGeneration，旧会话结果丢弃。
- `SealStepEvent`：eventId、stepIndex、sealId、证据时间区间、分数与本次阈值。匹配后记录消费关系。
- `CastCommand`：castId、skillId、origin、direction、可选目标、提交时间。独立于 SDK 和语音实现，执行器只处理有效提交。

新增 `SkillDefinition` SO 保存稳定 skillId、显示名、口令、合法印序列、最低步骤与必需步骤、阈值减免与下限、释放模式、目标模式、时限、耗能、冷却、效果引用。引用模板时使用稳定 sealId 或源资产映射，不能依赖测试副本的对象引用恰好相同。所有面向调试的 Inspector 字段使用中文 Header、名称和单位。

### 模块落点与实现顺序

拟在 `Assets/SealCombat/` 新建独立运行时代码与训练场景，复用 Steam Link 场景的已验证 Rig，继续使用当前 XR Hands/Meta 输入适配。第一版模块：

1. `SealEvidenceAdapter`：接收实验台评分完成事件、复制证据、维护有限历史。实验台只增加必要输出接口。
2. `VoiceIntentSource`：统一模拟口令与以后真实语音入口，提供队列、采集时钟映射和去重。
3. `SkillCastController`：技能选择、局部阈值策略、步骤状态、超时、就绪和提交。自身可用合成事件测试，不直接读麦克风或生成粒子。
4. `CastAimAndRelease`：头向瞄准、腕部动作、有效地面和释放姿态。样本判定与效果表现分离。
5. `SkillExecutor`：第一版投射物和范围技能、受击目标、资源与冷却反馈。投射物检查从生成点到下一位置的路径与阻挡，忽略自身碰撞；不要仅凭终点重叠漏掉高速命中，也不要朝穿墙准星直接结算伤害。范围技能按目标身份去重，避免多 Collider 重复受伤。
6. `CastHUD` / `CastTraceRecorder`：只消费状态与诊断，不推进步骤或释放。

首轮先用模拟语音事件验证真实手部到命中的闭环，UI 明确标注“模拟口令”。提供倒计时脚本化输入，戴头显后无需腾出手点按钮。通过后接真实中文 KWS，同一事件接口不改状态机。再扩展连续多印、充能、束流和辅助锁定。

战斗面板显示技能名、已完成印、下一步、听取状态、就绪/轻推提示、瞄准点、剩余时间和冷却。开发面板额外展示所有分数、基础/有效阈值、追踪覆盖率、竞争分差、语音延迟和最近拒绝原因。复用现有中文字体和逐特征解释；不在战斗视野持续铺满 45 个特征。

日志记录 castId、事件与采集时间、阶段迁移、原始分与有效阈值、失败原因、释放姿态、命中结果和配置版本；失败按状态变化或限频打印。骨骼 JSONL 继续保留；默认只记录语音识别事件元数据，需要排查声音问题时再启用音频采集。自身技能提示优先用提示音，避免完整咒语回放再次被识别；这一情况要单独做负例测试。

验收至少包括：正确组合一次释放；语音/动作任一错误不释放；持续同印和追踪恢复不重复计步；延迟/重复语音不复活已取消会话；低质量或覆盖不足不因阈值减免通过；就绪前推手不释放；只转头/后仰不触发；无目标按技能规则处理；暂停/断连后清理；命中不穿墙/不因多个 Collider 重复扣血；UI 显示的阈值与实际判定一致。最后再在 Steam Link 和 Quest 原生分别测端到端延迟与帧时间。
