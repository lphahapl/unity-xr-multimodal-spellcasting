# 线性 RPG：当前决定、可玩切片与开发验收

更新：2026-10-30。**本文件是当前玩法方向和新场景交互的优先入口。首个切片已实现并通过 Unity 编辑模式与真实Play检查，尚未进行新动作的 Quest 真机验收。** 操作见[使用说明](LINEAR_RPG_QUICKSTART_ZH.md)。历史训练场继续用于技能对照，不据本文件假定旧场景已经改用新规则。

## 1. 已确定的范围

采用**线性关卡＋轻量 RPG**：沿固定流程推进，通过固定解锁、少量隐藏法术、轻量升级购买和检查点形成成长。不以大量 NPC 任务为当前内容规模，不先搭建通用任务树。

暂缓肉鸽随机奖励池、局内构筑、每局结算和复杂装备词条。旧调研文件名中的 `ROGUELITE` 只表示当时问题背景，不表示仍要实现肉鸽循环；其画符、位移和官方 API 依据仍可参考 [来源核对](ROGUELITE_GLYPH_LOCOMOTION_SOURCES_ZH.md)。

首版采用全虚拟 VR，Quest 优先，PICO 保留设备适配边界；MR 后续评估。多人当前只保留未来同房间 PvE 契约。人工 VR 位移改变虚拟玩家根节点，真实同房空间映射描述共同现实坐标，两者必须独立管理。首版瞬移/闪避不能直接解释成未来同房玩家的真实位置变化。

## 2. 已确定的操作 A

### 2.1 左手导航：进入、选点、确认

1. 左手食指伸直进入导航状态。单手指向是导航意图，**不是独立结印触发条件**；该状态不能同时向技能匹配器提供新结印证据。
2. 进入时记录本次手部参考位置。食指/手小范围移动几厘米，按前、后、左、右四向选择场景预设导航点；不要求大幅挥臂，也不采用无限距离射线点地。
3. 指定方向悬停达到确认时间后，只提交一次选点。必须回到中区才能再次触发；持续保持同一方向不能连续瞬移。方向阈值、死区和驻留时长为配置及真机调参项。
4. 确认时重新验证当前目标、允许区与落点。目标不可用则拒绝并显示原因；不凭历史候选传送。

玩家有 `OnNode` / `OffNode` 两类位置状态。导航到预设点可进入 OnNode；闪避允许离点成为 OffNode。下一次导航从**当前实际虚拟位置**选择目标，不自动吸回原点，不先补一次回点位移。节点资格判定容差需在配置中明确。

默认使用瞬移并保持玩家真实头姿，不强制旋转 HMD。目标方向与当前视线夹角小，不是自动改用平滑移动的充分条件；连续镜头位移需要独立模式、显式选择和舒适性验收。落点和路径检查按当前移动类型分别处理，不能认为“最近 NavMesh 点”已经证明安全可达。

### 2.2 右手张掌短划：闪避与火球使用

默认在左手导航准备期间，右手张掌后向方向短划发起闪避，方向来自有效的新手部动作。保持普通结印状态时不接受闪避，减少挥手误触发。先明确前、后、左、右的映射与阈值；**八向自动避敌、威胁评分和自动挑方向仍待讨论，本轮不实现。** 闪避请求需检查路径/落点碰撞、允许区及追踪有效性。

手中有火球时，右手前推优先归火球发射：

- 火球尚未准备好，也不能把同一次前推动作降级成前闪。
- 一次前推被持球使用消费后，火球因发射消失不能使同一动作追加前闪；必须观察新的动作和重新武装。
- 侧闪、后闪可以保留手中火球，手持时限继续正常推进。
- 闪避开始清除导航候选的驻留累计，不能在闪避落地后因旧驻留立刻又传送。

### 2.3 双手放低取消

双手**都可靠追踪**、同时进入低位并短暂保持才取消；保持时间候选为 **0.4 秒**，低位高度、退出滞回和时间由配置及真机验证决定。追踪丢失、数据陈旧或缺少关节不是“手已放低”；无效样本应停止/重置低位累计。

取消清除待施法输入、未完成画符、未发射手持物，并隔离旧输入证据；**不清除已生效护盾，不召回飞行物，不撤销既成伤害**。已成功生成/加持后的收起不退款，冷却保留。完整口令“取消施法”与显式 UI 继续作为备用，遵循新场景相同的取消范围。

旧训练场的“双手张开分开保持”和“按顺序取消持物/扩展效果/护盾”属于历史兼容行为；新 `LinearRpgTest` 场景采用上述低位及限定范围规则。旧行为不会因设计文档更新而自动迁移。

### 2.4 同帧冲突与输入消费

| 顺序/条件 | 当前规则 |
|---|---|
| 暂停、失效、追踪丢失 | 先阻止依赖相应证据的新动作；无效追踪不生成取消、笔画或重新结印事实 |
| 已确认取消 | 先清待施法/未发射物、导航驻留和未完成笔画；同帧不再激活技能 |
| 持球时的前推 | 由发射路径独占，即使未就绪也不转前闪；记录本次动作消费 |
| 合法方向闪避 | 清导航驻留；侧/后闪不清持球，检查路径与落点 |
| 左手导航 | 独占本次选点证据，暂停新结印/画符证据；驻留一次确认，回中再触发 |
| 其他合法技能输入 | 按现有单印三模式匹配；同一证据不重复施法 |

跨帧仍须保存动作消费/重新武装状态，不能只靠当前是否持球来决定前推用途。恢复追踪后建立新基线，不能把丢失期间的位置跳变补成短划。

## 3. 数据归属与施法资源

| 数据层 | 内容 | 持久化边界 |
|---|---|---|
| 共享 SO 定义 | 玩家基础上限/恢复、技能配方/费用/冷却组、关卡与节点配置 | 编辑器资产；不写当前 HP、剩余 CD 或某玩家领取标记 |
| 角色永久成长 | 解锁技能、等级、货币、已购买升级；以后需要时再增加装备资格 | 稳定 ID 与版本化值；固定成长为主，不存随机局内构筑 |
| 冒险进度 | 当前关卡、检查点 ID、已领取隐藏奖励 ID | 检查点可恢复；隐藏奖励领取幂等，不能靠重载重复领 |
| 玩家运行态 | HP、MP、CD、护盾、手持槽、当前存活与位置状态 | 场景/会话拥有；存档只保存明确允许的检查点快照，恢复规则另验收 |
| 临时输入 | 结印/口令缓存、导航驻留、短划基线、笔画轨迹、输入代次 | 不进玩家存档，切场景/取消/输入失效按职责清理 |

实现入口为 `Assets/SealCombat/Runtime/Rpg/Data/`、`Runtime/Locomotion/`，场景集成由 RPG 控制器接线。具体类和菜单以集成后源码、场景和验收记录为准，目录名不构成功能完成证据。更详细的长期扩展见 [玩家数据设计](PLAYER_DATA_DESIGN_ZH.md)。

初步数值：最大 HP **100**、最大 MP **100**；成功耗费后延迟 **2 秒**再按 **5 MP/秒**恢复；火球 **20 MP**，护盾 **15 MP**。这些是本切片初值，需可配置。现有技能 CD **3 秒**作为兼容基线，不因新文档自动重写旧资产。

施法的资源规则：

1. 识别失败、待匹配取消、资源不足或生成失败均不扣 MP，不新建成功 CD，也不重置回蓝等待。
2. **成功生成手持物或成功加持时**才提交 MP/CD；之后收起或持握超时不退款。火球发射是成功手持物的使用，不再次收费。
3. CD 按技能组保存，换装或切换配方不能绕过仍有效的 CD。组 ID 要稳定，不能临时取中文名或资产路径。
4. 沿用单个共享手持槽和持有时限；不能靠重复激活叠出多个手持物。占槽行为以配置和明确拒绝结果表达。
5. 操作复杂度的收益由配方/技能设计定义，不能把识别相似度直接换算为伤害，也不让较多 MP 自动降低识别阈值。

本轮可通过同步激活回调接入单一内置效果的资源检查与成功记账。这**不等于**已实现通用多效果 `Prepare/Commit/Rollback`、来源 token 护盾账本或网络事务；这些保留在后续设计中。外部效果必须遵守返回成功前后的资源与失败清理契约，不能以一个 bool 声称所有副作用都能回滚。

## 4. 下一阶段候选：画符和多模态配方

画符是后续的时序轨迹输入，**不是图片分类训练**。先用少量单笔符号验证可辨性与输入冲突，再决定是否扩展：

- 进入绘制时锁定胸前绘制平面，定义明确开笔/收笔；用真实 3D 指尖采样投影到本次 2D 平面。
- 少量单笔 `$1` 模板作为候选。正例之外必须加入自然手动、结印过渡、导航、负例和模糊拒绝；明确旋转是否改变语义，不能随归一化偷偷抹掉方向。
- 进入导航或丢失追踪时停止当前笔画。滤波/插值可供显示，不能把补帧当新识别证据，不能跨失效段连成合法笔画。
- 未来配方可配置口令、结印、画符及其顺序/时间窗；当前代码仍只有**单印配方的纯印、纯咒、组合三模式**。

画符、属性克制、敌人韧性/硬直、完整升级商店、完整剧情当前均未实现。画符方案、闪避阈值和低位保持候选不能被当成已经实测的准确率或舒适参数。

## 5. 最小阶段与当前状态

| 阶段 | 交付与边界 | 状态 |
|---|---|---|
| A：首个可玩切片 | 新 `LinearRpgTest` 场景；玩家 HP/MP/CD/检查点；节点导航、方向闪避、低位取消；复用火球/护盾；中文 UI 与 Inspector | **已实现，Unity检查通过；Quest动作与舒适性待实测** |
| B：输入与战斗 | 少量单笔画符、负例与模糊拒绝；敌人属性及韧性/硬直；明确配方收益 | 下一阶段设计，未实现 |
| C：线性内容与成长 | 连续关卡、固定解锁、隐藏法术、升级购买和检查点恢复；补充存档迁移与奖励幂等 | 已有三阶段试炼、固定奖励、隐藏盾与火球升级原型；完整商店和剧情仍后续 |
| D：设备与未来扩展 | Quest 原生语音/性能与 PICO 验证；以后再评估 MR、同房 PvE | 设计预留；不安装网络框架作为 A 的前置 |

首次切片不要求先完成通用多效果事务、完整装备系统或通用 NPC 任务框架。保留现有四个训练场用于回归，不用新场景替换其历史验证含义。

## 6. 首个切片验收与真机清单

Unity 6000.3.10f1 中已执行：15组玩家/存档检查、28组手势状态/物理移动检查、47组原技能核心回归，以及真实Play中的效果与RPG联动检查。准确组数、时间与逐项结果见[编辑检查](../Logs/linear-rpg/build-check.json)和[播放检查](../Logs/linear-rpg/play-check.json)。真实Play使用模拟手姿、显式命令和作弊击靶，未宣称验证了真实手势或麦克风。

| 范围 | 必须看到的结果 |
|---|---|
| 场景与旧行为 | 新场景可独立打开、中文说明准确；四个旧训练场的原有触发/发射/取消保持兼容；资产未被隐式改成新默认 |
| 节点导航 | 四向选择、一次驻留确认、回中再触发；持续指向不重复；无效目标拒绝；OffNode 从当前位置选点、不自动吸回 |
| 头姿与移动 | 瞬移保留真实头姿；路径/落点阻挡、墙边/低顶/跨层有明确结果；不以夹角小偷偷平滑镜头 |
| 发射与闪避 | 持球前推只发射；未就绪不前闪；发射当帧及后续同一动作不追加前闪；侧/后闪保留球；闪避清选点驻留 |
| 低位取消 | 双手有效并保持才取消；单手低位/追踪丢失不触发；待施法与手持物清除，护盾与飞行物保留；恢复后旧证据不重放 |
| 数值与资源 | 识别/生成失败、待匹配取消不扣 MP；成功生成后收起不退款；成功只扣一次、CD保留且换配方不绕过；回蓝等待正确；单手槽及持有时限有效；盾后剩余伤害扣 HP |
| 检查点 | 合法检查点记录与恢复可见；关卡/检查点 ID 校验；临时输入不恢复；死亡/重生的 HP/MP/持物规则在 UI 和日志中清楚 |
| 证据与真机 | 区分可重复逻辑检查、Unity 场景检查和 Quest 实机；真机补充追踪丢失/遮挡、快速手动、自然动作误触发与舒适性记录 |

仍需实机完成：左右手导航准备与短划阈值、低位手腕是否在相机视野内、遮挡/恢复与自然动作误触发、连续战斗舒适性、真实音频误报与漏检。画符尚未实现，“取消未完成笔画”是未来接入契约。
