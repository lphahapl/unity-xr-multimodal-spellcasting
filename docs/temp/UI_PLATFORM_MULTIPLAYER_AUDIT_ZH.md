## 结论

总体方向可以共存：**Quest 单机全虚拟 VR 线性 RPG 优先；增加腕饰入口和独立教学面板；MR/PICO 后续；同房 PvE 目前仅保留设计契约。** 已有模块和数据分层可继续使用，但尚未完成平台独立输入、通用 UI 输入仲裁或网络权威边界。此次发现的是多处旧描述失效及 UI 尚缺的接线约束，不是已经具备跨平台/多人能力。

## 2. UI 开发前必须守住的接线

| 风险 | 现有代码证据 | 后续设计约束 |
|---|---|---|
| 菜单抢写阻断值 | `LinearRpgController.Initialize/LateUpdate` 绑定回调并写投掷抑制 | 在同一个决策点组合战斗/UI/练习状态；不由多个脚本争写 bool/委托 |
| 点腕变结印/闪避 | `RpgGestureState.ProcessSealProtection` 按双腕距离保护，右掌独立短划 | 已受理 UI 样本不再流入战斗消费者；进入前已有结印/持球优先 |
| 关菜单变技能取消 | `CancelCasting`、`CancelInputOnly`、`SkillEffects.ClearAll` 作用范围不同 | 分离 CloseLauncher、ClosePanel、ExitPractice、CancelCasting 的语义；关闭 View 不清效果 |
| 示例音误施法或误取消 | `SkillTestController.ProcessVoice` 先处理取消，再检查阻断 | 语音入口会话隔离、清队列与尾音门控；不能只关一个 UI 开关 |
| 本地 UI 暂停清理共享世界 | `OnApplicationPause/OnDisable` 清效果，`Time.timeScale<=0` 会清飞行物 | 普通菜单不切 `timeScale`、不停用主控；未来房主时钟与本地输入生命周期分开 |
| 提示内容与技能配置分叉 | 当前已有稳定 skillId、配方与效果 SO | 教学内容引用技能 ID/教学资源，实时值读状态；画符未实现要明确标示 |

## 3. 给后续设备与联机保留的边界

| 层 | 允许复用 | 不应跨层承担的职责 |
|---|---|---|
| 设备输入 | 项目定义的手姿/有效性/时间与口令事件；未来显式关节/腕轴映射 | UI/玩法不直接读 OVR/PXR；渲染补帧不能充当新识别证据；不把所有 provider 的 valid 当同一种置信度 |
| UI 与教学 | 腕饰主题、课程/技能 ID、面板状态、关闭策略 | 不直接写 HP/MP、生成有伤害效果、读取远端人的手作为本机输入 |
| 战斗本地实现 | 匹配→命令→资源/效果→只读状态；当前同步回调暂保留 | 网络前须区分 Pending/Committed/Rejected，不能把发送成功当施法成功 |
| 空间 | 手部 tracking-local、VR 虚拟玩家空间、物理房间/会话空间各有含义 | VR Rig 位移不等于现实移动；`WorldLocked` 不等于已持久化/已共享物理锚 |
| 网络 | 未来 NGO＋UTP/Host 候选，权威命令与状态 | 不同步全部原始骨骼历史、每颗粒子或个人菜单布局；局域网连接不负责现实对齐 |

共享房间的 MR 模式需要单独的移动政策，不能只给当前 VR 场景打开透视就沿用 0.8 米闪避/节点瞬移并称为真实同伴位置。允许的真实走动范围、虚拟战斗位置和其他玩家可见的现实身体表示都必须独立设计。空间失效进入房间协调流程，个人查看菜单则只影响本机交互，两者不能混为一谈。

PICO 接入先做独立探针，验证手姿、腕轴、系统手势、音频和必要 MR 能力，再做模板标定及构建隔离；不为当前 UI 安装 PICO/XRI/网络 SDK。现有 SteamVR 手追踪通过也不证明厂商原生透视、共享锚或 Android 中文语音已通过。

## 4. 下一步顺序

1. 保持 Quest 移动/投掷真机调试；用真实录制确认误触发和延迟。
2. UI 实施时先接最小统一交互状态，再做左腕三入口与一张结印卡；验证关闭/点按/持球优先和追踪恢复。
3. 复用配置扩充咒语教学、音频隔离与安全练习；画符保持预览，识别单独研发。
4. 在出现第二个实际输入后端或开始 PICO 探针时落地平台契约；原生 MR 与同房坐标分阶段验证。
5. 单机系统稳定后再实施局域网命令/状态和权威时钟，最后验收同房空间对齐。当前仍只留文档契约。
