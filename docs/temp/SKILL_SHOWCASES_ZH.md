# 三个技能试炼场景：使用与特效替换

日期：2026-10-29。本文依据当前场景生成器、`SkillScenario` 和技能效果代码说明使用方式。文中的测试时序与数值对应默认配置。已完成编辑器运行检查，结果见 [交付验收记录](SKILL_DELIVERY_QA_ZH.md)；尚未完成 Quest / Steam Link 硬件帧率验证。

三个场景从现有 `SkillTest` 复制，保留骨骼追踪、中文 HUD、语音接收器及原有三个配方。它们增加的是训练环境、视觉预置体和护盾数值演示，没有新增领域技能、环境遮罩或玩家生命系统。

同日配置架构升级后，三个场景共享 `Configuration/试炼技能目录.asset`；新配置方式以 [项目 README](../README.md) 为准。技能列表已可扩展，本文的“三个配方”指初始默认配置。

## 1. 创建与打开

退出播放模式后，在 Unity 菜单中选择：

**Tools → NarutoVR → 技能展示 → 创建三个独立试炼场景**

生成器 `SkillShowcaseSetup.BuildAll()` 先确保四种特效资源存在，再创建缺失的场景。**已经存在的场景会直接保留，不覆盖自定义布局。** 再次执行创建菜单不会把已修改场景重置成模板，也不会自动把生成器中的新布局套到已有场景。

| 场景 | 打开菜单，均位于 `Tools → NarutoVR → 技能展示` | 场景路径 |
|---|---|---|
| 焰道 · 火球靶场 | 打开火球靶场 | `Assets/SealCombat/Scenes/FireballRange.unity` |
| 澄心 · 护盾试炼 | 打开护盾试炼 | `Assets/SealCombat/Scenes/ShieldTrial.unity` |
| 合契 · 组合施法试炼 | 打开组合施法试炼 | `Assets/SealCombat/Scenes/ComboSanctum.unity` |

打开菜单要求当前场景没有未保存修改。也可在 Project 窗口直接打开对应 `.unity` 文件。原始 `Assets/SealCombat/Scenes/SkillTest.unity` 继续作为基础测试场景。

## 2. 三个场景共用的操作

| 输入 | 默认效果 |
|---|---|
| 完成子印 | 立即获得自身护盾 |
| 直接念完整口令“护体咒” | 立即获得自身护盾，不要求双手追踪有效 |
| 寅印与“火球术”在同一 8 秒窗口内匹配 | 右手生成火球；先印后咒、先咒后印均可 |
| 火球生成后，持球手向前轻推 | 发射火球；头向准星辅助瞄准 |
| “取消施法”或张开双手分开保持约 0.5 秒 | 按当前取消层级清输入或收起效果 |

手印仍需通过模板分数、覆盖率、消歧和连续保持检查；口令不会免除追踪质量要求。未消费的持续合格寅印可以保持着等待口令，已经消费的动作则需有效退出原姿态后才能重新施法。默认三个技能各有 3 秒冷却。

火球需要**当前右手**的有效生成锚点。历史手印匹配成功不等于可以用历史坐标生成火球。手槽占用、当前手追踪无效或冷却中会拒绝本次尝试，条件恢复后不会自动补发；请重新输入。

默认轻推参数为：生成或追踪恢复后至少准备 0.25 秒，在 0.15～0.6 秒内向前移动至少 0.12 米。只看持球手的新有效动作；整体向前走或单纯后仰不能代替手部前推。未发射火球最长持有 10 秒；追踪丢失时隐藏，约 0.5 秒仍未恢复则消散。

### 电脑快捷键与免手测试

| 快捷键 | 功能 |
|---|---|
| `F6` | 默认倒计时 5 秒后注入模拟“护体咒”事件 |
| `F7` | 默认倒计时 5 秒后注入模拟“火球术”事件，仍需实际寅印 |
| `Esc` | 取消待匹配输入；没有待选时优先收起持握火球，再取消自身加持 |
| `F8`，仅护盾试炼 | 准备/开始一轮护盾测试；已准备或正在测试时停止 |

F6/F7 和电脑按钮是**模拟口令**，不会测试麦克风或关键词模型。倒计时可在 `SkillTestController` 的“模拟口令倒计时”中调整。真实语音通道按 [语音接入说明](SKILL_VOICE_SETUP_ZH.md) 启动，并查看 HUD 的通道状态。

可以在摆手前按 F7，再在倒计时期间完成寅印；护盾试炼默认在首次获得护盾后自动开始，不要求摆好手印后再点鼠标。

## 3. 焰道 · 火球靶场

夜色庭院包含石板、台阶、门柱、橙红火纹和青色地面引导。玩家前方保留射击通道，三个漂浮靶按从初始站位的水平距离约 3 米、5 米、7 米布置。左侧另有墙后靶，用于区分“命中目标”和“被场景墙体阻挡”。

建议顺序：

1. 完成寅印并念“火球术”，确认 HUD 提示右手已经生成火球。
2. 用头向准星看向近靶，准备后持球手前推，观察飞行与命中爆散。
3. 分别尝试中靶、远靶及左侧墙后靶；墙体应先阻挡经过它的火球，不能透墙扣靶生命。
4. 再做持握取消、持握超时或追踪恢复测试，确认旧动作没有被当作新的发射动作。

默认火球伤害为 25，训练靶生命为 100；靶子击破后约 2 秒恢复。这里的生命属于**训练靶**，不是玩家生命。火球飞行默认寿命 4 秒；命中事件先锁定一次结算，不靠视觉粒子或多个 Collider 反复扣血。

## 4. 澄心 · 护盾试炼

圆形青蓝试炼台、环形立柱和能量线用于观察护盾表现。独立世界面板显示测试轮次、下次测试倒计时、当前护盾和未吸收伤害。

默认勾选 `SkillScenario` 的“首次获得护盾后自动演示”。在本次播放中首次通过子印或“护体咒”获得护盾后，开始有限的一轮测试。若先按 F8 时还没有护盾，测试会进入准备状态，等获得护盾再启动。

以一轮开始时护盾为 100、途中不刷新或取消护盾为例：

| 相对本轮开始时间 | 输入测试伤害 | 护盾吸收 | 剩余护盾 | 未吸收伤害 |
|---|---:|---:|---:|---:|
| 约 0.5 秒 | 30 | 30 | 70 | 0 |
| 约 3.0 秒 | 30 | 30 | 40 | 0 |
| 约 5.5 秒 | 30 | 30 | 10 | 0 |
| 约 8.0 秒 | 30 | 10 | 0 | 20 |

首击准备时间默认 0.5 秒，后续间隔默认 2.5 秒，共最多 4 次。实际执行落在更新帧上，可能稍晚于表中时间；不会在卡顿后同一帧追补多次伤害。首击提早安排，使通常的四次测试能在默认 10 秒护盾期限内完成。

测试只调用 `SkillEffects.AbsorbDamage`。第四次的“未吸收伤害 20”只是报告值，**不会创建玩家 HP、扣玩家生命或伪造死亡结果**。护盾已经结束、被取消或效果执行器停用时，测试停止，不在无盾状态持续刷伤害日志。

F8 或右上方按钮可停止/重新准备一轮；“首次获得护盾后自动演示”复选框控制自动启动。关闭自动选项不会把已经开始的一轮当作未开始；如需立即停止，用 F8 或停止按钮。已完成一轮后，可先用 F8 准备，再重新施加护盾。暂停也会停止本轮测试。

可调参数位于 `SkillScenario`：每次测试伤害、测试间隔、首击准备时间、每轮最多测试次数和自动演示开关。改变这些值后，表中的默认时序及结果不再适用。

## 5. 合契 · 组合施法试炼

紫青色几何阵法、石柱和远端靶强调两条流程：

- **先印后咒：** 完成有效寅印，再在匹配窗口内念“火球术”。
- **先咒后印：** 先念“火球术”，在 HUD 等待状态下完成有效寅印。

口令结束与有效手印保持区间必须落在同一个不超过 8 秒的区间内，不是前后各允许 8 秒。窗口外输入会超时；换成另一个完整技能口令会替换待选并清理旧证据。匹配满足后直接激活，火球生成后的轻推属于使用持握物，不是追加一次施法确认。

地面阵法是视觉装饰。它不改变触发模式，不执行领域伤害，不修改真实环境透视或遮挡，也不限制玩家移动。当前仍只有子印加持、护体咒加持和火球术三个配方。

### 当前语音限制

当前采用关键词检测，不理解整句否定或意图。已给定真人录音中，“不要释放火球术”也产生了“火球术”事件；场景说明因此提示：**请直接念口令，否定句也可能命中。** 引擎对事件标签的完整匹配不能消除语音检测器已经输出关键词的这个问题。

长句“领域展开，诛伏赐死”只在独立实验词表中做了离线检测，没有加入默认游戏词表或连接领域技能。详细证据见 [真人录音离线基线](PLAYER_AUDIO_BASELINE_ZH.md)。不能把一次口令命中、静音检查或模拟口令按钮当作意图理解或真实环境准确率证明。

## 6. 四个视觉预置体

| 预置体路径 | 当前用途与约定 |
|---|---|
| `Assets/SealCombat/Prefabs/火球.prefab` | 白金核心、流火外壳、旋转能量弧、火星与飞行尾迹；由技能生成和发射控制 |
| `Assets/SealCombat/Prefabs/护盾.prefab` | 青色护腕符环与薄层辉光；当前优先跟随左腕，左腕不可用时使用头前的提示位置 |
| `Assets/SealCombat/Prefabs/命中爆散.prefab` | 火球碰撞时的一次性震环与火星；具有自动结束生命周期 |
| `Assets/SealCombat/Prefabs/地面阵法.prefab` | 场景装饰用的双层旋转几何印与浮尘，不参与伤害、识别或移动限制 |

菜单 **Tools → NarutoVR → 技能 → 创建缺失的华丽特效预置体** 调用 `SkillVisualAssets.EnsureAssets()`，只创建缺失资产；现有 Prefab、材质及手工编辑不会被该入口重写。

### 替换某个场景的视觉

1. 复制需要修改的 Prefab，或建立 Prefab Variant，保留原资产作为对照。直接修改共享原 Prefab 会影响所有引用它的场景。
2. 打开技能目录中的目标 `SkillDefinition`，进入它引用的效果配置资产，在 `ProjectileEffectDefinition` 或 `ShieldEffectDefinition` 中替换视觉/命中预置体。共享效果资产的修改会影响所有引用它的技能。若仅改某场景，应复制目录、目标技能及其效果资产并逐层重新绑定。
3. 地面阵法是场景中的“场景装饰阵法 · 不产生领域效果”实例。可替换该实例或使用其 Variant；保留地面位置、XZ 朝向和适当的离地间隔。
4. 进入播放模式，分别观察持握、发射、命中、追踪恢复、取消与暂停后的清理。修改尺寸后同时核对实际火球碰撞半径，不只看画面大小。

替换时遵守当前约定：

- 火球根节点以中心为原点，视觉按约一单位直径制作。运行时会把根节点缩放设为效果资产 `ProjectileEffectDefinition.radius` 的两倍，默认约 0.13 米；需要改变轮廓时调整子物体或在效果资产中修改半径。放大视觉子物体不会自动扩大命中范围。
- 护盾 Prefab 按米制尺寸制作，当前模型是约 0.12 米的护腕表现；运行时不会自动把它变成全身罩。护盾显示位置与数值吸收相互独立。
- 地面阵法本地 XZ 为水平面，原始外半径约 1.15 米，线面自带少量离地偏移。三个场景各自设置了实例缩放。
- 默认 `SkillVisualMotion` 仅负责旋转、呼吸、尾迹与淡出。保留默认飞行尾迹切换时，该组件及其绑定应位于火球根节点，供效果执行器切换持握/飞行状态。
- 命中爆散使用根节点的 `SkillVisualLifetime` 自动结束，默认约 1.1 秒；替换件没有该组件时，投射物会补上。较长粒子动画需要与生命周期一起调整。
- 视觉 Prefab 不负责输入、伤害或玩家属性，不应附带额外伤害脚本或物理碰撞体。默认生成资源不含 Collider，效果运行时也会禁用视觉中的 Collider；真正命中仍由 `SkillProjectile` 处理。

效果资产中的火球或护盾视觉字段留空时，会使用基础球体/光环；命中爆散字段留空则不生成命中视觉。`SkillEffects` 上旧视觉字段只在技能没有引用效果资产时生效，保留用于旧场景兼容。替换 Prefab 不改变玩家生命或技能配方。

## 7. 静态预览与验收边界

菜单 **Tools → NarutoVR → 技能展示 → 生成三张场景构图预览** 对应 `SkillShowcaseSetup.PreviewAll()`。它要求退出播放模式且没有未保存场景，逐个单独打开场景，结束后恢复此前的场景布局。

预览使用临时相机，从 `(7, 5, -7)` 朝向 `(0, 1, 4)` 渲染 1600×900 图像；不改变游戏 HUD 相机或真实头显姿态。为观察场景构图，原有随头 HUD 暂时隐藏，预览结束恢复；场景粒子会显式模拟并清理。输出为：

- `Logs/preview-FireballRange.png`
- `Logs/preview-ShieldTrial.png`
- `Logs/preview-ComboSanctum.png`

这些是编辑器静态构图图像，不能证明真实手追踪已经完成发射链，也不能证明 Quest 或 Steam Link 的帧率、延迟和持续运行表现。场景使用共享材质、程序化几何与受限粒子，没有额外实时灯光或昂贵后处理；这些设计选择仍需用目标硬件 Profiler 实测，不能换算成已验证的 FPS。

目前已通过 3 个场景绑定检查、47 项核心匹配检查、20 项效果检查，以及护盾四击的实际 Update 循环检查。效果检查使用隔离的临时玩家与模拟骨骼，覆盖预置体绑定、碰撞与取消等行为，不等于真人完成过发射动作。

菜单 **Tools → NarutoVR → 技能 → 渲染四种特效预览** 另可生成 `Logs/vfx-fireball.png`、`vfx-shield.png`、`vfx-impact.png`、`vfx-sigil.png`。使用实际预置体，固定粒子抽样；没有额外为截图添加 Bloom、HDR 或色调映射。图片只验证外观。

三个新场景的头显 HUD 使用较高的 Canvas 排序，避免场景说明牌盖住实时文字。后续手工改动后如再次遮挡，可在退出播放并保存场景后使用 **Tools → NarutoVR → 技能展示 → 修复头显面板遮挡**。

玩家数据目前仍是 [设计文档](PLAYER_DATA_DESIGN_ZH.md)。已存在的数值能力是护盾、训练靶生命和技能冷却；尚未实现统一 `PlayerRuntime`、玩家能量、解锁装备或版本存档。场景里的护盾演示不改变这一状态。
