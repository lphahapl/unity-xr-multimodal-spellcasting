# 腕饰菜单、独立面板与输入归属

生命周期补充（2026-10-31）：Hierarchy 的“腕部界面 · 自有世界根”是运行时生成的临时容器，每个 `WristMenuView` 对应一套；无预览的编辑状态应为0套。曾发现编辑测试销毁组件后仍残留该容器，以及隐藏调用给未创建的视图反而分配对象。现由 `ExecuteAlways` 保证编辑生命周期执行，隐藏操作不再隐式创建，`ReleaseVisuals` 幂等清理自建根/材质/音效；`WristViewEditorLifetime` 在重编译前清理并重置菜单状态。只处理自建资源，不销毁用户字体或其他场景物体。回归同时检查连续创建/销毁、禁用、重载钩子和完整测试后的孤立根，原始复现见 `Logs/wrist-lifecycle-20261031`。

更新：2026-10-31。**当前默认改为抬左腕＋右指点腕饰开关，射线轻捏时确认，详见第 9 节。** 第 1～8 节保留调研和旧版自动握拳抬腕的演进记录；冲突时以第 9 节为准。腕饰入口、独立面板策略与 RPG 输入仲裁已接入 `LinearRpgTest`；真人头显验收待做。固定安全练习课程、动作示范资源及画符识别尚未实现。

## 1. 这种模式有没有先例

**腕部入口、小型手菜单、从手上展开独立面板都有成熟先例；“握拳＋抬腕唤出、放腕关闭”不是已经验证的通用标准。** 以下是设计依据，不代表已在本项目试玩，也不构成使用率统计。

| 一手资料 | 能支持的结论 | 使用边界 |
|---|---|---|
| [Rec Room 官方 VR 操作说明](https://zendesk.recroom.network/hc/en-us/articles/4424652450071-VR-Controls-and-Gestures) | 看腕打开表盘、可配置另一手点表盘打开、菜单可脱离腕部 | 文档描述控制器路线，是产品先例，不能作为 Quest 裸手握拳精度证据 |
| [Microsoft 手菜单指南](https://learn.microsoft.com/en-us/windows/mixed-reality/design/hand-menu) | 小菜单用于短操作；复杂内容转独立面板；注意条件和交互时固定位置有助减少误触 | HoloLens 的位置/尺寸建议不能直接当作 Quest 验收标准 |
| [Unity XRI 3.3 Hand Menu](https://docs.unity3d.com/Packages/com.unity.xr.interaction.toolkit@3.3/manual/hand-menu.html) | 已有手锚、掌朝向可见性和跟随参数的组件 | 工程没有安装 XRI；该组件也不等于自带我们的握拳规则和冲突仲裁 |
| [Ultraleap Hand Controls](https://docs.ultraleap.com/xr-guidelines/Components/handcontrols.html) | 小型随手控件用于快捷入口，更多内容可放到环境中 | 是可借鉴的手部交互模式，不意味着采用其硬件/SDK |
| [Meta Hands UI，2026-09-24](https://developers.meta.com/vr/design/hands-ui-best-practices/) | 不建议可点菜单持续贴腕移动；允许从腕部召出后固定在世界中；触碰要有清楚音画反馈 | 官方选项菜单手势是非惯用手掌向上食指捏合，握拳抬腕属于游戏自定义交互 |

[Meta 旧 Wrist Buttons 页面](https://developers.meta.com/vr/design/wrist-buttons/)已标记弃用/归档。不能再把旧系统腕按钮当成当前推荐接口；这也不表示应用内自定义腕饰被禁止。未来要验证各设备系统手势是否抢占输入。

## 2. 推荐的外观和操作

左腕放一个护腕、咒印手环或符箓饰物，常态仅显示装饰。**装饰跟腕，展开的按钮暂时固定，详细面板独立存在。** 这样仍像从手腕唤出功能，但点按目标不会跟另一只手一起漂移。

1. 左手握拳、抬到头显视野内，腕饰正面朝向玩家，并稳定短暂停留，显示三个入口：**结印 / 画符 / 咒语**。使用 HMD 朝向近似注意区域，不假定有眼动追踪。
2. 握拳仅为唤起条件，不要求一直攥紧。菜单展开后固定在腕旁可触及的位置；短连线或光效表达其来自腕饰，右食指点按有悬停、按下和确认反馈。
3. 点开某入口后创建/切换详细面板，重复点同一入口聚焦已有面板，不无限生成。默认一张主要交互面板，允许一张不抢输入的速查卡。
4. 左腕**有效追踪且明确放低**时小菜单收起，腕饰保留；已打开的详细面板不因此消失。入口关闭和子面板关闭必须是两个状态，子面板不要挂在会被关闭的腕部对象下。
5. 提供显式重定位与关闭入口。菜单展开/回收、按钮确认使用不同短音效；示范口令由玩家主动播放，不自动播放技能名。

位置、抬腕角度、开启/关闭滞回、短停留和目标尺寸均为配置项。首轮可以用约 0.25～0.40 秒开启确认做试验，但这是**项目候选值**，不是官方标准或准确率保证。开启与关闭阈值分开，避免在临界高度闪烁；不在此阶段给出未经真机验证的固定厘米尺寸。

## 3. 面板分别怎么关闭

| 对象 | 保持方式 | 关闭/失效规则（拟定） |
|---|---|---|
| 腕饰 | 跟随有效左腕 | 丢追踪时隐藏/淡出，不在原点显示假手环 |
| 三入口小菜单 | 召出后暂时固定 | 左腕有效放低后关闭；丢追踪立刻禁点，宽限后隐藏，不发施法取消事件 |
| 结印/咒语速查卡 | 显式固定，允许战斗中阅读 | 关闭键或返回；放腕不关；只读显示不占战斗输入 |
| 可点详细面板 | 固定于当前场景空间 | 关闭键/切换面板；交互结束释放输入所有权；不以玩家暂时移开视线立即关闭 |
| 练习面板 | 课程状态独立 | 显式退出；双手有效放低可取消本轮练习，面板仍可显示；不触发战斗效果 |
| 画符说明 | 当前仅预览 | 标“识别尚未实现”，不展示虚构得分或成功结果；未来练习完成另行验收 |

“关闭菜单”“退出课程”“取消施法”是不同命令。若战斗输入仍有效且双手满足既有低位取消条件，按战斗规则收起未发射物；不能让 `OnDisable` 或面板销毁间接触发 `ClearAll()`。已生效护盾和飞行物不因关面板而消失。

## 4. 与现有手势如何避免冲突

左拳与左食指导航姿态不同，但这并不自动消除冲突：右手仍可能持球/闪避，双手靠近仍可能触发结印保护。必须按“已有动作优先、已取得的 UI 输入不再流入战斗”处理。

| 情况 | 拟定规则 |
|---|---|
| 已持球、导航、闪避或结印保护中 | 拒绝打开交互菜单，不打断动作、不排队等会儿突然弹出；已有只读卡可以保留 |
| 满足左腕召出条件 | 仲裁器受理后再显示可点菜单；同一批输入不能又算成新结印/闪避 |
| 右指靠近菜单 | 属于 UI 点按，不因双腕靠近反向进入结印；仅排除已归 UI 的样本，不全局关闭结印保护 |
| 点按/拖动/练习中 | 对应手部输入由 UI/课程消费；战斗不能拿同一动作导航、闪避或释放技能 |
| 只读速查卡显示 | 不永久阻断手势或语音；玩家可以对照卡片施法，必须清楚区分“实战”与“练习” |
| 结束交互、丢追踪或关闭 | 取消未提交点击/驻留；恢复后重新建立中性基线，不把松拳、收手当成新投掷/闪避 |
| 播放中文示范音 | 播放前在语音接入处停止命令消费，清旧队列、隔离会话/迟到结果，尾音结束后提示跟读 |

源码接线约束：`OfficialHandPoseDetector` 已有左右 `closed/valid` 可复用，但仍依赖 Meta 特征，不能称为平台无关入口。`LinearRpgController` 已占用 `SkillTestController` 的单一阻断/激活/取消回调，并每帧写 `ThrowInputSuppressed`。实施时应**在 RPG 的统一输入决策处组合 UI 状态**，而不是菜单脚本再抢写这些字段；不用停用 RPG 主控来打开菜单，否则当前生命周期会清理效果。`ProcessVoice` 在 `VoiceInputBlocked` 之前处理取消口令，因此仅设置该回调不能隔离示范音。

最低落地分层为：腕饰/入口检测 → 统一交互状态 → 面板控制/内容资产。面板按稳定技能 ID 查配方，不把印序、咒语、CD、MP 文案各复制一份。教学资源和 UI 状态独立于玩家战斗存档；具体类名等实现时确定，不先增加大批空接口。

## 5. VR、MR、PICO、多人边界

- **VR**：本期“固定”是虚拟场景世界空间，不跟手、头或玩家根节点移动；传送后可关闭入口并显式重定位面板。追踪原点/场景变化时作废旧点按历史，不能让旧坐标被当成新目标。
- **MR**：另行定义物理房间锚或会话空间，不能直接把 Unity 世界坐标称作真实共享锚。菜单不遮掉现实同伴/障碍；原 VR 节点瞬移、闪避不能直接用于改变真实同房位置。
- **PICO**：共享内容、面板状态与关闭策略；手势来源、腕部轴、系统保留手势、点按与音频接入单独适配、验收。保持现有 Meta 接线直至有对照数据，不直接复制 Quest 模板阈值宣称兼容。
- **多人**：个人菜单、教学卡和指针默认本机私有，不复制每帧 UI Transform。需要让队友看到的腕饰可作为角色外观复制。购买、装备、施法等改变游戏状态的按钮最终提交权威命令，等结果确认；关闭菜单不等于撤销已提交请求。普通菜单不暂停房间时钟；同房空间对齐失效的协调暂停属于另一项房间规则。

`IActorPoseSource`、`IWorldFrameMapper`、`ICombatCommandPort` 等仍是既有文档中的拟建契约，不是本轮已经落地的接口；命名沿用[多人方案](MULTIPLAYER_LAN_PLAN_ZH.md)和[兼容方案](QUEST_PICO_COMPATIBILITY_PLAN_ZH.md)，不另建相同职责的一套。

## 7. 旧版自动抬腕实现与操作（2026-10-31，已被第9节替代）

入口：`Assets/SealCombat/Scenes/LinearRpgTest.unity`。场景对象 **左腕术式菜单与教学卡** 的 `WristMenuController` 配置输入与各子面板策略，`WristMenuView` 配置字体、颜色、尺寸与非语言提示音。所有配置使用中文 Inspector 标注。

1. 左手握拳、抬到视野内胸前位置，稳定约 **0.24 秒**。默认**无需扭腕对准头显**；可接受低于头部 0.50 米、头向 60° 范围内的手腕。装饰跟腕，三个入口召出后固定于世界；打开后可放松手指。腕边显示开启进度和需要调整的原因。
2. 右食指靠近按钮，向按钮正面点入；或右食指指向按钮，看到高亮后，拇指食指捏合，再在同一按钮松开确认。捏住进入按钮、跨按钮松手、丢追踪或重复快照不会确认。
3. 教学卡提供 **上一页 / 下一页 / 重新定位 / 关闭**。内容读取当前技能目录，不另复制 MP、CD、口令和印配方。当前是文字速查，尚无印的示范图片/幽灵手/完整课程评分。
4. 子面板的 **放下左腕时关闭 / 允许射线捏合翻页或关闭 / 允许食指近距离点按** 分别配置。默认 **结印和咒语卡放腕保留，画符预览放腕关闭**；这只是可改初始配置。更改策略不需要改代码。
5. 入口开启、点按和交接中暂时占用战斗输入；放腕低位持续 **0.12 秒**才关闭入口及配置为随腕关闭的子面板。取得左手低位或放松手指持续 **0.18 秒**的有效观测后，且没有 UI 点按/开启过程时交回战斗，**无需右手配合收拢或保持在视野内**。只读卡保留时可正常战斗，不暂停时钟。丢追踪本身不算放腕/释放；未完成交接前失去左手时需把左手带回视野放松。已完成交接后失联不会重新锁住战斗。
6. 持球、已有导航、双手结印保护时不接受菜单唤起；完成动作后需重新放松再握拳。关入口、关卡、失去追踪都不调用技能 `ClearAll`。双手低位取消仍属于战斗规则。
7. 传送、明显 Rig 变化、追踪来源切换或 XR tracking-origin 更新时关闭旧界面并取消旧点按，避免错位点击；重新抬腕召出。不改变 HMD 局部位置/旋转。

实现分层：

- `WristMenuInput`：项目世界姿态与观测时刻 DTO；`LinearRpgController.ReadWristMenuFrame` 接现有骨骼和官方基础手形。
- `WristMenuState` / `WristPointerState`：有效性、保持、输入归属、重备、捏合/近按边沿。
- `WristMenuController`：子面板策略、按钮命中、分页内容与世界重置；没有扣 MP、施法、联网或改存档命令。
- `WristMenuView`：second 账号 Astra High 返回的程序化 UGUI/腕饰视觉，经父代理审核、中文行高修正及样式刷新优化后落地。请求和完成模型均为 `gpt-6-astra`，状态 `completed`；记录 `Logs/wrist-ui-20261031/ui-result.json`。该账号没有直接操作 Unity。
- RPG 主控统一组合 UI 与既有输入门控；进入/退出清未提交骨骼与口令证据，增加独立语音消费门控，阻挡 UI 期间的取消口令及交接前结束的迟到事件。未播放任何中文示范音，尚不承诺完整 ASR 示范回声隔离。

自动检查入口：`Tools/NarutoVR/线性RPG/运行完整编辑模式回归`、`运行独立存档播放检查`；后台脚本 `Tools/Request-RpgCheck.ps1` 支持 `wrist-check`、`wrist-preview`、`configure-wrist`。`configure-wrist` 备份磁盘场景及当前内存修改后接线，重复使用不会重建或覆盖已有菜单设置。

MR/PICO 后续只共享 DTO 以上的状态、策略与内容，当前追踪适配仍依赖项目 Meta/OpenXR 管线。个人 UI 不写入战斗存档、不广播网络状态；同房 PvE 与物理空间对齐仍仅设计。

本轮自动验收：313 项编辑模式检查（含 33 项腕饰与指针检查）、37 项效果检查、30 项真实 Play 集成检查，共 380 项通过。Play 测试使用隔离存档与合成 UI 姿态；不等于真人捏合射线稳定度或设备性能验收。预览图已检查中文标题、正文、页脚和按钮裁切。记录：`Logs/wrist-ui-20261031`；完整报告来自 `Logs/official-hand-poses/editor-suite.json` 与 `Logs/linear-rpg/play-check.json`。

## 8. 抬腕易操作配置（2026-10-31 后续优化）

第 7 节操作已更新为本次默认值；第 2～6 节保留设计及后续课程要求。此轮使用 second 账号 Astra High 复核输入归属与单手释放边界，父代理核实 `RpgGestureState.Reset/ProcessRight` 的首帧仅建立原点行为，并实现、测试与应用配置。模型完成记录位于 `Logs/wrist-ease-20261031/review-result.json`。

- 唤起从 0.30 调为 0.24 秒；开启高度从低于头部最多 0.38 米放宽为 0.50 米，注意区域从 45° 放宽到 60°。这些是候选舒适配置，尚未测得真人准确率。
- 掌面/手背朝向改为可选，默认关闭；仍要求官方握拳状态、有效骨骼、合理距离和已有动作优先。
- 稳定半径从 7 厘米放宽到 12 厘米，使用“手腕位置减头部位置”的平移相对量，避免身体平移时误清零；不用旋转的头部局部坐标追着转头补偿。
- 新增 0.09 秒手形/角度短波动宽限：只保留进度，不把无效区间加入保持时间。追踪真的失效仍立即清空开启证据。
