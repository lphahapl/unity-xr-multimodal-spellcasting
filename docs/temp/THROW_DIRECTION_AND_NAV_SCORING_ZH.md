# 投掷方向与导航融合评分

更新：2026-10-30。场景：`Assets/SealCombat/Scenes/LinearRpgTest.unity`。

## 结论与边界

单帧手骨骼只能说明姿态，无法唯一确定真实受力。游戏需要的是离手速度方向：使用一段带观测时间戳的腕部轨迹，结合握拳/捏合释放边沿估算速度。加速度二阶求导更容易放大光学追踪噪声，本版不据此推算力量。

火球仍在腕骨局部偏移处生成，成功投掷后沿估计方向按技能配置匀速飞行（当前9米/秒），不自动转向头部或吸附敌人。握姿检测继续使用现有官方四指状态及捏合距离迟滞。

## 参考方案与取舍

- [Meta Interaction SDK RANSACVelocity](https://developers.meta.com/vr/reference/interaction/v203/class_oculus_interaction_throw_r_a_n_s_a_c_velocity/)提供近期轨迹估计和尾段排除，针对释放延迟及追踪噪声。本机已安装SDK也包含此实现。本次参考其时间回看思路，没有直接增加Meta投掷组件依赖；跨平台快照仍可接入Quest/PICO。
- [Unity XRI XR Grab Interactable](https://docs.unity.cn/Packages/com.unity.xr.interaction.toolkit%403.1/manual/xr-grab-interactable.html)提供投掷平滑时长和样本权重曲线。本项目使用真实观测时间，而非渲染帧数定义拟合窗口。
- [Unity XRI Gaze示例](https://github.com/Unity-Technologies/XR-Interaction-Toolkit-Examples/blob/main/Documentation/Gaze.md?plain=1)展示了视线辅助交互思路。当前项目以HMD中心射线代表头部视线，没有接入眼动数据。

第二账号已实际调用 `gpt-6-astra / high`，返回模型同为 `gpt-6-astra`。父代理提供官方资料与本地代码，Astra完成文本审查，未自行联网或改工程。审查结果见 `Logs/throw-observation-20261030/second-astra-review.json`。采用“释放起始冻结＋回看＋加权拟合”；没有照抄建议中的180ms导航驻留，保留用户现有650ms确认。最大采样间隔保留120ms；残差初始25mm，均需用真实数据调参。

## 已复现的问题

旧版在首次四指全Open时才冻结方向。实际输入可能经历 `Closed → Neutral → Open`，Neutral期间手已经收回，旧版仍持续更新短轨迹。合成对照中先向前运动、进入Neutral后收回，80ms后Open，旧算法未能保持向前发射。

实际失败报告：`Logs/throw-observation-20261030/direction-red.json`。这证明代码存在该失效模式；尚不能证明它是用户所有真机跑偏的唯一原因。坐标来源、预测误差及快速动作丢追踪仍须通过真实记录核验。

另一个独立问题是同帧消费延迟口令后，使用更早缓存的时间调用技能Tick，误触“时钟回退”保护。已将Tick取时移到口令处理之后，真实回退保护保持不变。实际红/绿对照见 `clock-red.json` 与 `Logs/linear-rpg/clock-check.json`。

## 新投掷流程

1. 腕部与手形必须属于同一观测帧，追踪有效、新鲜且高置信。握持确认60ms后进入准备。
2. 第一次有效 `Closed → 非Closed` 记录释放起点，冻结候选轨迹。Neutral只冻结，不发射；重新Closed撤销候选，并重新确认握持。
3. 拟合释放起点前120ms内、排除最后10ms的真实观测，至少4个样本、跨度至少40ms。重复时间戳不累计时间。
4. 使用指数时间权重（50ms衰减常数）最小二乘拟合 `p(t)=p0+v·t`，再做两轮Huber重加权。残差过大拒绝；不会靠平滑强行接受异常追踪。
5. 全Open持续25ms后提交已冻结速度。Neutral/确认总等待超过180ms则要求重新握住。静止松手不会发射，可再握持尝试。
6. 保留0.65～12米/秒速度门槛、相对身体位移至少55mm、过期/跳变/间隔保护。导航或闪避平移Rig后清空投掷输入。身体整体平移不能当甩手。

修改位置：`HandThrowState`负责纯计算；`SkillEffects`使用结果发射并提供可选诊断事件。配置位于 `Assets/SealCombat/Configuration/LinearRpg/效果_fireball.asset` 的“投掷参数”，新增项均有中文字段名。

## 移动选点

仍先伸直左食指、其余三指收拢，稳定200ms，再前后左右平移约5cm选方向。进入导航时锁定水平参考朝向，之后转头不会改写四方向。右掌四向闪避和结印保护保持原流程。

先通过同场景注册、显式邻接、实际地面、同楼层高度、身体占位及视线无遮挡检查，再在对应方向扇区内评分：

`S = (0.45×方向一致 + 0.30×手指射线贴近 + 0.15×距离偏好 + 0.10×头部意图) / 有效权重之和`

- 手指射线使用有效食指根关节到指尖方向，起点为指尖；按射线到节点落地点的几何距离做软评分，不要求击中一个很小的碰撞体。瞄准远点可覆盖默认近点偏好。
- 头部意图内部合并水平朝向和中心射线贴近度；不把同一HMD方向当成两套独立传感器。后方选点时停用头部项，无有效手指射线时停用手指项，并重归一。
- 新点领先当前点至少0.12分并保持120ms才切换。切换中暂停旧目标确认；切换后重新开始650ms驻留。当前点硬条件失效立即撤销，评分不能越过墙或楼层检查。
- 驻留后移动，手回中立才能再次选点；路径、落点圈、驻留进度与提示音跟随最终候选。HUD显示总分及分项分数。

导航网格扩展为5×5，沿实际庭院地面布置；旧9个节点的ID、位置与三个检查点保留。附近3.1米内补充邻接，使同方向可以选择一格或两格，原有自定义连接不删除。配置入口幂等，保存前另备份场景。

## 诊断与测试

播放模式下菜单 `Tools → NarutoVR → 线性RPG → 录制45秒投掷诊断（播放模式）`，或从项目目录运行：

```powershell
./Tools/Request-RpgCheck.ps1 record-throws
```

输出 `Logs/throw-captures/throw-时间.jsonl`，仅记录投掷路径中的真实输入：观测时间、腕部/头部位置、握持状态、冻结窗口、拟合速度/RMS残差、拒绝原因、最终输出速度。45秒或15000条自动停止；退出Play或重载也关闭文件。没有开启麦克风或图像录制。

建议每种握持做正前、斜前、向上各5次；分别记录误发、漏发、离手方向是否稳定。自动回归包括延迟张掌收手、72/90/120Hz与毫米级噪声、Neutral不发射、重新握持、离群点、整体身体平移、跳变/过期/重复观测，以及导航换点、后退、遮挡、楼层和完整驻留。

自动测试是合成轨迹及Unity集成检查，不代表真机方向精度、触发成功率或舒适性已经通过。最新报告见 `Logs/official-hand-poses/editor-suite.json` 与 `Logs/linear-rpg/play-check.json`，均包含时间和 `hardwareTested`。

后台播放首次向上投掷检查失败，加入逐帧记录后原算法复跑通过；已保留该失败，不能据此声称后台运行始终稳定。记录显示渲染观测间隔不均、有效窗口有时仅4～5样本，因此正式Play投掷夹具改为跨真实LateUpdate注入固定50Hz的合成观测时钟，隔离渲染调度；真实输入仍用原快照时钟。另有独立低采样率检查，确认不足4个样本时拒绝而非凭空补样。初次失败未留逐帧数据，不能把其具体原因判为已证实。
