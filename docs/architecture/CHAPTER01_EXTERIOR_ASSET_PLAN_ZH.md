## 方向与实施顺序

用户要求补齐光秃外景、修正建筑与世界观不符、消除普通物件悬空，并为新旧山体和物件提供真实 LOD。依据[世界观架构与全系统规范](../world/KAO_GONG_LU_DU_WORLD_SETTING_ZH.md)、[世界观白皮书](../world/考工律度_世界观设定白皮书.md)和[校规庭与量水道制作单](开场教学与首枚铜叶/07_校规庭与量水道制作单.md)，本轮落实的是天工司的工官建筑、水利与校器遗构，不套用明清古镇街景或日式庙亭外形。

以青灰石承重、青冈栎木梁柱、哑光青铜构件和白石刻度表达建造逻辑。柱脚、台基、桥墩和树根必须落到实际表面；除已接受的失度表现外，不用普通房屋、岩石或陈设的悬空充当世界观。定界铜基石维持工坊亚稳定区的既有解释保留，室内木格窗、门洞、既有教学机关与主路线不得被外壳封住。

实施按三步推进：先完成结构、接地和可通行连接；再补山脚岩层与稀疏成簇植被；最后放置工作台等陈设并接独立运动。[首章外景指南](../guides/CHAPTER01_EXTERIOR_VISUALS_ZH.md)记录当前候选、实际配置与发布/设备验证边界。

## 连通、接地与 LOD 的共同验收

1. **先验证实际表面。** 普通物件对父代理传入的真实三角网格高度做四点或九点支撑检查；无有效地面必须失败或跳过，不能用临时公式假装采样成功。柱脚、树根和墩底允许小量入地，房屋不能靠埋掉半个门窗掩盖高差。
2. **固定出入口与关卡顺序。** 西、东支路从校验门前分出；门庭、北坊支路在校验后区域。建筑开门与接路不能形成绕过校验门的捷径。原主线机关、窗洞、门槛与碰撞顶部约 -0.03m 保持；需要调整的旧栏杆由父代理单独列明。
3. **逐档查真实几何。** 非平凡组的 LOD0、LOD1、LOD2 必须是不同复杂度网格且三角数严格下降；小件可以单级。原山脊目标每件 2304→576→144 三角形，连续谷地 12800→3200→800，降级取同一已存在网格的表面采样，不重写地形高度。主山末级剔除阈值保持很低，避免突然消山。
4. **按区域合并。** 自然层按八块合并为每块最多四个材质 Renderer，步道按合理空间段合并；不能全场一块，也不能把每片苔、每根枝条保留为独立 Renderer。活动内环、门扇与触发保持必要独立层级。使用硬切换、不启用 CrossFade；远级关闭投影，碰撞不随 LOD 消失。
5. **实走与实看。** 门口、庭院、渠岸、门框、三工坊连接点分别检查；九点支撑通过不能替代侧面悬空、树冠遮挡、屋顶/山体相交及护栏封路的实际画面与通行检查。主场景发布前由父代理保留脚本、音频和未授权碰撞，执行隔离验证及最小合并。

## 性能口径与状态边界

本项目自行采用 **72Hz、每帧约13.89ms** 的设备目标，CPU/GPU 是否达标必须看真实 Quest 指标。离线视锥整网格三角数、选中 Renderer 数、全部 LOD Renderer 组件数以及实际 draw calls 是不同统计；不能互相替代，更不能用单目截图或离线 Editor 返回的零值证明性能通过。

2026-11-09 核查的官方 [VRC.Quest.Performance.1 Criteria](https://developers.meta.com/vr/resources/vrc-quest-performance-1/) 区分渲染率与显示刷新率：通常要求至少60fps渲染，交互应用采用72/80/90/96/100/120Hz等允许的刷新率，部分刷新率受设备支持限制；Application SpaceWarp 满足其条件时可采用半刷新率渲染，并存在页面列明的例外。因此，**本项目72Hz目标不等同于“VRC统一要求至少72fps”**，也不表示本轮已启用或验证 AppSW。

[性能历史调查](../../Logs/exterior-world-lod-20261109/performance/findings.md)仅作为本任务曾经收集的技术依据；其中旧版“Meta至少72FPS”的说法不采用，以本节官方 Criteria 核查为准。性能调查正文的纠正由父代理处理，本文件不代改历史报告。
