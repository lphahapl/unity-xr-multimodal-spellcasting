# 手部与准望匣资产：显示范围、骨架与交付要求

核对日期：2026-11-02。状态：设计/交付方案；已核对项目依赖和官方文档，未导入本轮美术模型、未做头显验证。本页区分平台接口、项目建议和概念图，不能把出图尺寸当成工程或人体工学验收。

## 可见前臂长度与器具尺寸

Quest手追踪接口不规定模型必须显示多少厘米前臂。标准OpenXR手部关节集含手腕、手掌与手指共26个关节点；该手部关节集本身不提供完整前臂/肘部骨架。可见前臂长度由虚拟手臂方案决定，不能因画出较长前臂便宣称具有肘部追踪。[OpenXR手追踪](https://registry.khronos.org/OpenXR/specs/1.1/html/xrspec.html#XR_EXT_hand_tracking)

本项目左手方案：建议腕横纹向肘方向显示140—160mm，示意图取150mm。依据为：尾环端离腕25mm，金属主体含外露尾环的纵向长度95mm，所以最靠肘端距腕约120mm；再留20—40mm作为模型收边余量。150mm是本项目道具布置推导，不是Meta推荐值，也不是用户手臂实测。模型近肘端用紧贴的袖口/麻布收边，避免暴露空心截面。

| 项目 | 概念值 | 边界 |
|---|---|---|
| 金属主体 | 80×48×40mm，建议 | 高度包含实体圆度盘，不含绕臂绑带/搭扣/手臂包络 |
| 已收纳尾环外露 | 15mm | 超出金属外轮廓；手指捏持空间待验证 |
| 金属主体加尾环纵长 | 95mm | 不是含绕臂带子的三维整套外包络 |
| 叶片 | 总长85×基准宽22×基础厚1.8mm，含15mm尾环 | 公棱、槽、榫键尺寸与公差未工程验算 |
| 双绑带 | 各宽15mm，建议 | 连接耳/销、皮带、扣/固定环均归道具总成 |
| 六仓中心距 | 5.5mm，暂定 | 五片已命名铜叶＋一备用空仓；层距不等于已验证可达性 |
| 绘图参照手长/掌宽 | 185/82mm（当前项目参照，未从本地FBX实测） | 用于比较比例，不强制把所有玩家手缩放成此尺寸 |

匣长/参照手长=80/185≈43.2%；含环纵长95/185≈51.4%。保留共享规范后续采用的185/82mm作为项目参照，但标准26个手部关节点不规定185mm统一手长；本次未从SDK FBX测量它。纵向布局为25mm腕部间隙＋含环95mm器具＝距腕120mm，在150mm可见前臂方案中剩30mm收边。这不等于对全部用户解剖尺寸、前臂围度、碰撞或头显视野的保证；能否完整看到还取决于视距、抬腕角度、摄像机裁切与遮挡，需要建模和真机检查。旧05图按人工选点粗查，主图器具/手长约79.4%，与标签不符；透视、不同平面和选点误差使它只能作为明显失配的判断，不能当摄影测量。完整选点与算式见[实际出图与比例核对记录](../visuals/20261102_zhunwang_hand_leaf_schematic/07_v3_worn_design_generation.txt)。

## 骨架与模型交付

1. 从本项目当前SDK的默认手模型/骨架导出副本作为基准，再绑定自定义网格。保持关节层级、关节朝向、绑定姿势和导入缩放约定，不凭概念图猜骨名，也不将通用角色手骨架直接当作SDK手骨架。Meta官方替换流程保留原armature，重新蒙皮并映射到HandVisual；按其流程导出FBX时不增加leaf bones。[Meta自定义手模](https://developers.meta.com/vr/documentation/unity/unity-isdk-customize-hand-model/)
2. Unity XR Hands路径以Wrist为顶层，Palm与各指起始关节在腕下，手指链层级须匹配驱动器。关节点数量不等于每个点都要有独立可变形网格骨段；不要为凑数伪造层级。[XR Hand Skeleton Driver](https://docs.unity3d.com/Packages/com.unity.xr.hands@1.7/manual/hand-data/xr-hand-visuals.html)
3. 左右手分别交付可蒙皮网格，检查真实尺寸/左右方向/指尖与追踪关节对齐。185mm仅作当前项目参照；早期190mm图稿保留为当时绘图值，运行时需遵循选用SDK的手部尺寸与骨架驱动方案。
4. 掌指关节、指间关节、拇指根部、虎口、腕部保留可变形布线；用张掌、握拳、捏合、指向、项目手印和腕屈伸验证，不把外观静态正确当作蒙皮正确。
5. 指环跟随对应指骨；准望匣保持刚性并归前臂挂载体系。双绑带可作为总成内独立子网格，但与连接耳、搭扣有连续装配关系，不作为手部麻布的一部分，不随五指弯折。
6. 可见前臂不能简单全部绑到会屈伸的手腕/掌骨。较长前臂与匣体需要独立前臂参考、虚拟手臂IK或适配的身体/手臂驱动方案；是否采用追踪扩展及其真实可用性须单独核对。不能把标准腕根位姿当成完整前臂方向。此项尚未实现/验证。

## 表面、性能与验收边界

- 铜叶自身外露面使用小篆感名称铭文；五种名称为方圆规印、勾股矩印、负衡律印、平准水度、直绳雷度。纹样不同，插接外包络和接口共用；不新增战斗效果。生成图的篆字须逐字校对后另做正式字稿/贴图，不能直接当作可用字体资产。
- 皮肤、布纹、浅刻铭文和磨损优先用贴图/法线表现；指环轮廓、指尖、虎口、捏持区和机械接口保留必要几何。材质尽量合图、控制透明和阴影开销，避免皮带/布边相互穿插与悬垂飘带。
- 旧资料中的双手连前臂2500—3500三角面、1—2 Draw Calls、2048贴图或每顶点最多4骨骼影响，不能统称Quest官方强制规格。它们可作为项目打样预算/建议核对，但需结合近景手部变形、双眼渲染、材质pass、场景余量与目标头显实测取舍；本次没有重新设定已验收的面数预算。
- 虚拟指环、麻布和铜匣是渲染外观，不应把它们宣称为提升真实摄像头手追踪的措施。手部识别与虚拟外观分层处理；真实手被遮挡或追踪丢失时需沿用项目数据有效性策略。
- 头显验收至少覆盖张掌/握拳/捏合/指向/手印、旋前旋后与腕屈伸、指尖点按、捏环抽取，以及短暂追踪丢失恢复。检查匣子不跟腕弯折、模型截面不露空、虚拟指尖不偏离输入位置、近距离无遮挡/穿模；当前均未实测。
