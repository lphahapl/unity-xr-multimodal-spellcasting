# 音乐制作与验收

把“想要的感觉”落实为可解释的音乐选择和可复现的成品。已有音乐先保留用户接受的主题、编制与用途，依据反馈调整相关层次。

## 先确定本次工作

- **新作**：从上下文提取用途、情绪/叙事、风格与编制、时长/播放方式、交付目标。能合理推断的先说明假设；只询问会改变方向的缺项。
- **改曲**：先确认正在听的版本，保留原文件。将反馈对应到时间点、声部和问题类型；有同源问题时覆盖整曲，避免只修用户指出的一处。
- **分析**：用户只要分析或方案时提供依据和可执行建议；用户已要求制作/修改时继续完成候选、检查和授权范围内交付。

执行制作前，只核实当前步骤需要的能力，如乐谱/MIDI、真实音源、合成器、DAW、渲染工具或听觉输入。需要选择工具、安装依赖或接通渲染时读[工具与渲染流程](references/toolchain.md)：区分发现、可加载、片段测通和成品验收。仅分析/规划时可将后续执行能力列为未核实，无需启动全部工具。文字规格、MIDI、合成试听、实录采样成品是不同交付物，按实际产物描述。

## 制作前的决策面

| 方面 | 要明确的选择 |
|---|---|
| 用途与叙事 | 服务谁、什么情境、表达什么变化；旁白/操作反馈是否优先 |
| 主题材料 | 可辨认的节奏与音程轮廓；哪些特征保留，后续怎样发展 |
| 曲式与呼吸 | 开头如何进入、段落如何连接、何处留白、结尾如何收束 |
| 旋律与和声 | 调式、音域、落点、张力与解决；是否真需要转调 |
| 人声与歌词（适用时） | 词意、语言重音、可唱性、歌手音域、主唱/和声与叠录 |
| 节奏与速度 | 拍号、速度、重音、长短句、休止；规整或游移的风格理由 |
| 配器与织体 | 谁领奏、回应、支撑；各声部何时进入、退出、换音区 |
| 音源与演奏 | 实录/合成身份、授权、音域、技法、起音、音准、换气与余音 |
| 动态 | 单音、乐句、段落三层强弱；最高和最低处如何服务用途 |
| 混音 | 前后层次、频段遮蔽、声像、混响、单声道兼容及总体响度 |
| 循环或适应性 | 一次性前奏、整曲循环、分段或分层切换；实际播放器能否实现 |
| 技术交付 | 格式、采样率、声道、压缩、资源引用、来源记录与可复现工程 |
| 验收 | 乐谱是否达意、波形是否可靠、真实试听是否完成；哪些仍未知 |

这些是决策项，不要求每首都具备前奏、高潮、转调、非对称段落或声部退出。安静音乐仍可以有呼吸；有意静态或机械节奏也可以成立。风格、用途与用户选择决定取舍。

## 从决策到成品

1. **新作或结构性重编写简短编曲表**：时间/小节、主角、动机操作、和声支撑、相对动态、过渡方式，读[创作与重编](references/planning.md)。局部修订复用原工程，仅记录修改目标与用户接受的保留项。
2. **先验证关键音色与片段**：用能包含问题的片段验证主题、目标音区、技法、来源和同源串音；若问题是整曲节奏或重复感，先做全长简化草稿。依据现有授权推进，保留用户接受的决定；只有会改变创作方向的不确定项才需补问。音源不适合时优先换源或改写。遇到音色、串音、重叠和单调反馈，读[音频复查](references/audio-review.md)。
3. **渲染候选**：保留可编辑乐谱/MIDI或原工程，以及音源、插件状态、控制曲线和处理链；具体映射与分轨约定见[工具与渲染流程](references/toolchain.md)。编曲的密度和力度变化应在输出中保留，避免自动平衡把变化抵消。
4. **分三层验收**：乐谱核主题与声部；波形核电平、时长、异常和接缝；真实试听核音色、叙事、呼吸、疲劳与循环感。没有听觉输入时将试听记为未完成，不根据峰值或音阶合规宣布“好听/和谐”。
5. **按请求交付**：提供版本化试听、正式文件、来源及简短变更说明。进入游戏或要求循环时读[循环与游戏交付](references/game-delivery.md)；保留现有引用及可回退版本。

问题归到创作、演奏/音源、混音或播放层，修改能解决根因的范围；涉及同源缺陷时仍覆盖整曲全部使用位置。检查修改处、相邻衔接及被保留的主题/编制，不因一次音色问题重生成整首。说明改了什么、为什么、做过哪些检查，以及尚未验证的听感。没有新增变化或失败证据时，完成既定检查后交付，不反复为提高代理指标继续改曲。

## 配合现有技能

本技能负责从音乐意图到实际音频交付的决策与验收；已有 `mc-workflow` 负责详细编曲规格 ARR-SPEC。需要该规格且本机有此库时读取入口与所需schema；简单局部修订保留原工程格式，不另造互相冲突的规格。

按当前问题选读已安装的专业技能，而非一次加载全库：

| 问题 | 专业技能 |
|---|---|
| 单调、没有前奏/转折、重复没有发展 | `mc-arrangement-arch`、`mc-development` |
| 旋律、和声、声部互撞 | `mc-melody`、`mc-harmony`、`mc-counterpoint` |
| 节奏、律动、演奏方式 | `mc-rhythm-groove`、`mc-rhythm-section` |
| 乐器搭配、拥挤或塑料感 | `mc-orchestration`、`mc-texture-layering`、`mc-sound-design` |
| 演唱、歌词与声部表达 | `mc-vocal-direction`；词曲关系由具体任务决定 |
| 混音层次与交付意图 | `mc-mix-intent` |
| 生成结果整体审计 | `mc-ai-tell-audit`，按曲种标适用项，避免把流行歌曲模板套到全部BGM |

未安装上述技能时，使用本技能的决策表及参考文件继续可完成的部分；不宣称已调用它们。已有游戏音频流水线继续负责SFX、环境音、语音与运行时调度，本技能补足音乐创作和成品验收。

## 可复用的只读检查

使用 `scripts/analyze_audio.py` 测量实际文件，命令与输出解释见[音频复查](references/audio-review.md)。它不会修改音频、判断和谐度或替代试听。需要改曲时结合分轨和乐谱诊断，再渲染新版本。
