# 音频复查

## 分开记录三种证据

| 层次 | 能验证什么 | 不能据此宣称什么 |
|---|---|---|
| 乐谱/事件 | 音符、音区、主题变化、声部占用、预期和声 | 实录源没有杂音、成品一定和谐 |
| 波形/频谱 | 格式、电平、起音、音高族、包络、接缝异常 | 有叙事感、音色自然、久听不疲劳 |
| 真实试听 | 音色、呼吸、层次、情绪、循环感、实际使用效果 | 未测试设备或场景同样通过 |

没有音频理解或实际听音能力时，完成可用的乐谱/数值检查，明确留下试听项。播放工具或生成文件不等于已经听过。

## 音源先于整曲

记录作者/库、授权与署名、来源链接、文件哈希、源格式、切片范围、实测根音和处理链。公开可下载不自动等于可发布；MP3试听源不标成无损母带，实录、合成和替代乐器按实际说明。

对实际使用的根音和目标音区取样检查：

1. 核实基频与八度映射，文件名的八度命名可能不同。调音参数正负与重采样方向必须实测。
2. 分别看起音、主体与尾音，区分另一声部、再次拨弦、噪声、自然颤音和非整数泛音。切点元数据未必包含全部后续起音。
3. 结合多个时间窗与谐波族判断串音；立体声分析保留两声道或平均功率，避免单声道相消误判。单个旁峰不自动代表另一个音。
4. 先换更干净的演奏、缩短受污染部分或撤去不必要补奏。确认的局部余音可尝试有限窄带减弱，比较目标泛音与起音是否保留。大量谐波重建、宽频去除或拉伸可能改变音色，不能只追求更干净的频谱。
5. 来源确认有问题后，按映射找整首全部使用位置，包括移调音符和循环边界；保留受影响事件清单。

## 从实际发声检查重叠

把起音延迟、延音/松键、自然尾部及效果尾部计入占用，不只看MIDI note-off。分别检查同一主奏前后音、主奏与伴奏、相邻句、跨循环事件。换气与演奏法按风格决定，没有统一适用于所有音乐的40ms间隔。

用户反馈“零碎、没有主题”时，先核完整乐句是否真正发声：固定的节奏轮廓有没有被保留，主题是否清楚陈述后才变化，每音独立起落或过密换气是否切断旋律。管乐区分句内连奏/吐音与句末换气，连续力度按整句组织；需要连接采样时检查交接电平、音高平台及句界，不能用逐音静音代替演奏验收。持音采样交接应标为编程连接，不称实录连奏。相同音高集合、合规音阶或零冲突都不能证明听众能认出主题。

先检查分轨，再检查完整混音。弱背景经过音与突出的低区二度簇影响不同；严重性判断包含时间、音高、时长、相对电平和音乐功能，不以消除全部二度为质量目标。

## 只读分析脚本

主要依赖Python、NumPy、SoundFile；SciPy用于4倍过采样峰值，pyloudnorm用于LUFS。先核现有运行时；脚本不联网、不安装依赖、不改音频。下例替换成真实路径，输出必须是新文件、父目录已存在：

```powershell
python -X utf8 <skill目录>/scripts/analyze_audio.py <音频路径> --out <新报告.json>
python -X utf8 <skill目录>/scripts/analyze_audio.py <音频路径> --out <新循环报告.json> --loop --sections <段落.json> --window-seconds 4
```

可选段落文件格式（秒，边界在实际音频内）：

```json
{
  "sections": [
    {"name": "引子", "start": 0, "end": 8},
    {"name": "主题", "start": 8, "end": 24}
  ]
}
```

报告包含哈希、格式、峰值、RMS、LUFS、4倍过采样峰值估计、等长窗口与指定段落。`--loop`才增加首尾差与局部变化比较。短音频、静音或缺少可选依赖时，不可用指标以`null`及说明表示。跨版本比较使用对应音乐段落，时长变化后不要机械比较同一秒数。

区分dBFS峰值、dBFS RMS、LUFS综合响度与LU响度差；分轨能量比例不是听觉占比。过采样峰值是工程估计，不冒充认证真峰值仪表。等长窗口极差不是标准LRA，稀疏休止会放大它。

首尾一秒若只有一侧包含新起音，会出现较大电平差；结合事件和不同长度的窗口判断，不把单个窗差直接判为断裂。

边界小于局部差分分位只说明未见突出样本跳变；首尾为零、过零点或加淡变也不能证明音乐与播放器无缝。脚本不输出“好听/和谐/循环通过”的自动判决。

## 可选FFmpeg复核

需要LRA、短时响度或另一套真峰值测量时，使用已验证的FFmpeg构建。按[官方ebur128说明](https://github.com/FFmpeg/FFmpeg/blob/master/doc/filters.texi)核对本机`-h filter=ebur128`；`peak=true`需要libswresample支持。以下PowerShell例只分析输入，输出到null，不写音频：

```powershell
& 'C:/明确的安装目录/ffmpeg.exe' -hide_banner -nostdin -nostats -i 'D:/明确的输入.wav' -map 0:a:0 -af 'ebur128=peak=true:framelog=verbose' -f null -
```

保留真实命令、版本、退出码与stderr总结：综合LUFS、LRA和true peak。静音、过短或门限以下材料的极值/零值须结合状态解释，不套通用通过阈值；多声道先核布局，mono是否按dual mono测量取决于实际播放方式。这里的FFmpeg true peak和脚本的4倍峰值估计分栏报告，数值可能有差异。测量不等于把作品统一到EBU默认目标，也不自动调用`loudnorm`改变动态。

## 收尾尺度

检查整个成品，重点回看首段、最密处、最弱处、全部修改处与连接段。分轨/全曲的参数与起点要一致，确认发布文件与验收文件哈希对应。简短报告包括需求覆盖、修正问题、数值结果、实际试听方式与未解决项；不编造综合自然度分数。
