# 2026-11-01 移动与腕部交互修复

## 当前操作约定

- 移动：左食指指向可达节点，准备0.12秒，同一节点驻留0.32秒。执行后移开射线或放松左手再选择。路径、碰撞、结印及UI占用检查仍有效。
- 主菜单：抬左腕，右食指主动靠近并点腕饰；再点关闭，放腕也关闭。主菜单随腕移动。
- 子菜单：射线高亮后轻捏确认，包含翻页、关闭、跟随开关和拖动条。子菜单不使用食指近按。结印/咒语卡默认放腕保留，画符卡默认放腕关闭，可通过closeWithWrist配置。
- 拖动：射线指向顶部拖动条，轻捏并保持。手前后、上下、左右移动以及转动射线都会改变面板位置；拖动时面板朝向头显。松开结束；追踪丢失或动作占用也结束，不补发旧点击。
- 跟随开启：位置跟随玩家Rig坐标，旋转持续朝向当前头显。跟随关闭且未拖动：保留当时世界位置和旋转。重定位/追踪坐标系重建仍按原策略关闭旧UI。

## 已确认的问题及修改

1. 实际LinearRpgTest场景序列化useRayNavigation=0，导致旧的食指位移模式仍运行。改为1，完整回归直接断言实际场景启用射线模式。
2. TickTap遇到每帧超过maxGap时反复清空放腕关闭计时，入口无法收起。观测中断后若收到新鲜、有效的低位手腕样本，直接隐藏入口；开启、点击仍保留连续观测保护。
3. FindTarget近按优先，且近按执行路径忽略drag，导致靠近拖动条无法轻捏拖动。子菜单统一使用射线轻捏，主菜单按钮保留近按。
4. 旧拖动只计算rayOrigin平移，转动射线不影响位置。改为捕获射线命中距离及面板偏移，以射线抓取点更新位置，并朝向头显。
5. 跟随模式原本只继承Rig旋转，不能持续朝向玩家。现在位置依旧按Rig跟随，朝向根据头显实时计算。

## SDK依据

本机Meta Interaction SDK的HandPointerPose读取IHand.GetPointerPose；IndexPinchSelector独立读取GetIndexFingerIsPinching。指针方向与选择事件是两条独立输入，不是两条可见射线。当前项目优先使用通过有效性和手边距离校验的SDK指针；SteamVR下无可信Aim时回退到腕部至食指根部方向。当前轻捏仍使用有效骨骼指尖距离及开合滞后，不宣称已经接入官方选择器。

## 腕部射线、轻捏与拖动遮挡（2026-11-01 更新）

电脑 Game 面板展开「运行状态与技能冷却」，查看腕部的射线来源、捏合来源、当前锁定目标、上次确认及拖动状态。Steam Link/PICO OpenXR 按两个通道各自的有效数据选择。FB Aim 扩展、标准 EXT 手部交互设备或 Meta 原生手均可供数；运行时不提供有效系统输入时，射线使用腕根到食指和中指指根中点，轻捏使用拇食指尖距离与迟滞。EXT 模式取有效 pinchReady 下的 pinchValue，0.75按下、0.35松开，中间区保持。标准扩展需要运行时支持且工程启用对应 Hand Interaction Profile，缺失时骨骼回退仍可用。实体点腕必须有真实食指尖。

拖动中丢样时停在原世界位置，持续有效捏合恢复后重新计算偏移再继续移动；有效松手即结束，即使当帧射线无效。超过 Inspector「拖动遮挡宽限」后安全结束，默认0.30秒。动作占用、关闭面板和空间重置也结束拖动。点击在来源变化或丢样时重新等待张开，避免旧目标误选。真机测试依次尝试：轻捏翻页、抓住拖动条短暂遮挡、恢复后继续拖动、松开、长时间遮挡。
