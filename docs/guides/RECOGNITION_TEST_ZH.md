## 录完后如何使用

1. 在原实验台中载入每个印的录制，生成对应模板草稿，检查目标最小值和最大值，再勾选“已确认模板”。仅有 JSONL 录制文件还不能识别，必须完成这一步。
2. 测试场景引用同一组十二印模板。退出播放后更新模板，下次进入测试会读取新范围。
3. 连接 Steam Link 后运行测试场景，放下控制器摆印。场景启动即进入测试模式。
4. 左面板显示识别结果、候选、保持进度、十二印匹配得分、阈值、覆盖率和手追踪状态；另外两块面板显示全部 45 项实时特征。
5. 想查某一个印为什么不通过，在实验台组件上选择“测试预期印”。它只选择诊断对象，不参与判定。未选择时，日志默认分析得分最高的三个模板，可把“诊断前几名”改成 12。
6. 在 Unity Console 搜索 `[结印测试]`。默认每 2 秒最多输出一次，分数会写成“得分 73.2/100，要求 80.0”，并列出各扣分特征的当前值、范围、容差、扣分。识别成功时不输出失败日志。

## 对 Gemini 表的评价与起步配置

使用的是工程根目录用户提供的 `NarutoVR_12Seals_FeatureConfig.xlsx`，不是 docs 中的早期空白表。

表内 12 个印各有 45 条规则，阈值均为 0.8、覆盖率均为 0.8、保持时间为 0.07 秒，角度软容差 15 度、距离软容差 0.015 米。每印有一个 Required 项。这可以作为试验起点，不能据此证明能区分十二印：目标区间尚需录制标定，权重也尚未经过正样本、无印及相似错误印验证。

按“先宽松起步，误报后收紧”的要求：使用表内权重、阈值、覆盖率、保持时间和软容差，默认不强制表内 Required。双手有效性检查、低质量过滤及 5 个百分点的相近印分差保护仍工作。

- 当前 Required 只在特征数据缺失或不被采纳时否决，不会因该特征数值超出范围而单独否决。
- 15 度、1.5 厘米是初始经验值，不是 Meta SDK 强制标准。Opposition 是标准手尺度归一后的距离，其 0.015 不能简单当作每个人真实手上的 1.5 厘米。
- 所有 45 项均有正权重，单个 2.5 权重项只占总权重约 5%。关键特征完全不匹配时，总分仍可能超过 80；相互相关的 Curl、Flexion 等特征还可能重复计分。
- UI 所说“置信度”显示的是规则匹配分数，不是正确概率，也不是设备追踪置信度。覆盖率与追踪质量另列。

测试配置位于 `Assets/SealLab/Resources/SealTestWeights.json`，由 `Tools/extract_test_weights.py` 只读提取工作簿第一张矩阵表生成。运行时克隆模板并应用权重，目标范围和启用状态来自原模板；原模板资产不被覆盖。新增或改表后需重新执行提取脚本。缺少标定范围的规则不会凭空生成，会打印提示。

有误报后，先对照两个混淆印的实测特征和扣分，再提高区分特征权重、收紧该项范围/容差或提高对应印阈值。用独立录制检验，不要只拿生成模板的那段数据自测。
