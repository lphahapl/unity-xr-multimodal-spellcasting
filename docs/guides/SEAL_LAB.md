# 结印数据与权重实验台

入口：Unity 菜单 `Tools > NarutoVR > Open Seal Lab Scene`、`Tools > NarutoVR > Seal Lab`。
实验场景为 `Assets/Scene/SealLab.unity`，原 SampleScene 保留。此工具是采集、调参和验证原型，尚未用 Quest 真机验证识别效果。

## 数据链路

`FromOVRHandDataSource → 独立的实际 Hand/IHand → SealFrame 原始快照 → SDK FingerShapes + 双手几何 → 面板/录制 → SealProfile 加权评分`。

官方 OVRHandsDataSource Prefab 的部分 Hand 经过 LastKnownGoodHand，会在失去可靠追踪时保留姿态。实验台新增直接连接 FromOVRHandDataSource 的 Hand 分支，识别与录制均读取该分支，不读取 LastKnownGoodHand、HandFilter 或 SyntheticHand。

每只手保存：连接/追踪状态、整手及各手指的置信标志、CurrentDataVersion、观测时间、Scale、各关节有效性、相对 TrackingSpace 的姿态、SDK 标准化腕部空间姿态。关节数量来自当前 SDK 的 Constants，不硬编码26。

版本变化的首次观测时间用于新鲜度判断，默认超过120ms未变化就标记过期；双手组合默认最多60ms观测时间差。这是应用观察SDK更新的时间，不能当成摄像头的精确采样时间，也不能保证每个版本都是新的光学测量。最多60Hz采集，不反复将同一版本当成新样本；任一手更新、有效性变化或过期变化仍会产生组合快照。单手快照版本可重复，以保留当时另一只手的上下文。

## 45个连续特征

每只手18项：五指 Curl、Flexion；拇指/食指/中指/无名指 Abduction；食指/中指/无名指/小指 Opposition。SDK不支持的小指Abduction、拇指Opposition不输出，避免将占位0误当成有效测量。

SDK角度保留度数；Opposition保留标准化手尺寸下的距离，显示为 `m@scale1`。不强行将所有量映射为0～1。特征计算调用SDK的 `FingerShapes.GetValue`，输入是冻结的原始快照，因此实时与回放使用同一套SDK算法。

双手9项：腕部距离、掌面法线夹角、同名拇指/食指/中指指尖距离、食指方向夹角、右手腕在左腕坐标系的XYZ位置。实际双手距离以米计量。掌面法线通过腕/食指根/小指根三点构造并按左右手校正；这是几何近似，不是SDK直接测出的真实掌面。退化三角形、必要关节无效、过期或双手时间差过大时输出N/A。

缺失值单独保存valid标志；数值0不是缺失标记。指间特征会合并相关手指的置信标志，双手几何会检查两只手的整体置信。系统不能从被遮挡的手指恢复真实姿态；后续按可见特征选择、容差和实测混淆情况调参。

## 使用步骤

1. 打开实验场景和Seal Lab窗口，接入Quest/Link后进入Play。无头显时出现UNAVAILABLE是正常边界，不生成模拟手势。
2. 面板显示左右手状态、版本、原始特征数值、单位和置信度；头显内的HUD显示摘要，绿色线条显示原始骨骼。
3. 选择印模板，填写录制标签，设置准备倒计时和录制时长，点击“准备录制”。默认先倒计时5秒供你摆印，再自动录制5秒并停止保存，不需要摆好印后操作鼠标。头显HUD显示剩余时间，并有准备、开始和结束提示音。可取消准备或提前停止；暂停应用或退出Play会取消准备/关闭录制文件，每30帧刷新缓冲。
4. 打开JSONL文件，通过滑块或按原时间播放，Scene视图显示录制骨骼。回放会重新计算特征，调模板后立即重新评分。
5. 对一个高置信的有效姿态点击“生成模板草稿”，得到初始中心与容差。也可选择录制标签，用整段录制生成目标分位区间。草稿不会自动启用识别。对照多次正样本、其他相近印、快速过渡动作和遮挡样本调整后，再勾选“已确认模板”。
6. 在每行编辑权重、Min/Max、软容差和必需标志。权重0表示不用该特征。保存模板修改；关闭窗口前需要保存资产。

十二个印的资产已经预留名称，但初始为空且未校准，不宣称已经能识别十二印。采集可先从2～3个外露特征差异较大的印开始。

录制目录显示在面板中，为 `Application.persistentDataPath/SealRecordings`。Quest独立包可在SealLab组件勾选 `Record On Start`，设置标签、Preparation Seconds和Capture Seconds后打包，启动后自动倒计时并录制。实际时长受Recording Limit Seconds（默认60秒）的上限约束。准备时锁定标签，采集中修改界面标签不会改变本次数据标签。独立包暂未提供手势操作的开始/停止按钮。录制只保存在本机/头显，不上传。

回放格式为UTF-8 JSONL，一行一个schema1的原始快照，含标签。读取时检查骨架长度、有效姿态有限性及时间递增；暂最多载入20000帧。不同骨架模式的文件不能直接混用，需要显式迁移关节映射。SDK升级可能改变特征算法，应保留SDK版本和原始文件。

## 评分规则

特征落在 `[Min, Max]` 区间内，匹配度为1；距区间d时，匹配度为 `max(0, 1-d/容差)`。

`总分 = Σ(权重 × 匹配度) / 全部正权重之和`。
`覆盖率 = 可用特征的权重之和 / 全部正权重之和`。

缺失/默认不接受的低置信特征贡献0，但其权重仍留在分母，避免只剩少量特征时分数虚高。必需特征缺失直接不通过；同时满足分数阈值和覆盖率阈值后，还需持续达到模板的holdSeconds（默认70ms）才发出 WhenSealRecognized。该时间过滤是原型的连续保持方式，尚未实现多印连招状态机或滑动命中窗口。

默认拒绝低置信特征，可按模板显式允许；这会提高可用性，也可能增加相近印误判。建议通过降低易遮挡特征权重、提高外露特征权重来调节，而不是仅凭连招预期自动放行。

## 实时测试与整段录制标定

打开JSONL回放、选择印模板与正样本标签后，可使用整段录制生成规则草稿：至少10帧双手有效且高置信数据，保留在至少80%有效帧中可用的特征，Min/Max为10%～90%分位，初始权重1。统计不等于已经验证准确率，草稿需确认并保存后才能用于识别。

点击“实时测试（不录制）”，直接摆印，面板及头显显示结果。预期印只用于对比，不参与评分。所有已确认模板同时比较；无达标者返回未知，两个达标印的分差不足minimumScoreMargin（默认0.05）时返回无法区分。持续达到holdSeconds后确认，追踪丢失清除结果。排名显示分数、覆盖率及最多三条偏差特征。

采集和实时测试共用SealRecognizer与SealScorer；测试不改模板、不录制。Inspector中实验台组件、头显显示组件、印模板和规则均有中文Header、字段名称及说明。源文件SealRecognizer.cs负责持续判定，SealTemplateFromRecording.cs负责录制分位区间统计。
