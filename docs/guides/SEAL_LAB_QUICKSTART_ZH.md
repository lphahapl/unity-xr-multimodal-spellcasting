# 结印实验台：使用、录制、调试与图片数据

> 本文保留录制与标定流程；当前电脑连接按 [Steam Link 开发说明](STEAM_LINK_DEVELOPMENT_ZH.md)。原生 Quest 手追踪曾做过成功对照，但不代表全部十二印或原生语音均通过。当前功能边界见 [文档索引](../README.md)，模板以正在使用的 SO 为准。

依据2026-10-28的实际工程代码编写。软件检查已通过，Quest真机追踪和十二印准确率尚未验证。当前采用加权模板，支持从整段录制统计目标范围、手动调整权重及实时测试；没有训练神经网络。

## 你的图片能做什么

本地目录 `C:/Users/鲁迅/Desktop/结印` 包含12张单印JPG和1张总览JPG。已查看总览和寅的详细参考图。这些是动作参考材料，不是当前识别器的骨骼训练集。

图片适合确定动作标准、寻找外露且有区分度的手指组合，以及指导戴头显的人做出动作。不能据一张正面照片确定实际腕距、被遮挡的指节姿态、追踪置信度或适合Quest数据的角度阈值。照片中的左右还可能受镜像影响，标定时以SDK的解剖左右手为准。

MediaPipe等工具能从图片估计手关键点，但它们的关节定义、坐标系和估计误差与Meta IHand不同；估计的3D也不能当作真实深度。混合真人、动漫插图、字幕、多个手部区域的参考图还需先明确要检测的区域。每类一张图片不足以验证泛化，旋转/裁剪增广也不能替代不同用户与视角。

推荐先按照片摆动作，用Quest采集原始骨骼，再调模板。以后若改用机器学习，可以使用这些带标签的Quest快照提取的特征训练小分类器，保留当前运行时数据接口。图片分类、图片关键点估计和Quest骨骼分类是不同的数据管线，当前没有实现自动互转。

## 第一次连 Quest 调试

按[Steam Link 开发指南](STEAM_LINK_DEVELOPMENT_ZH.md)连接 Quest → SteamVR OpenXR → Unity。打开 Steam Link 专用实验场景，放下控制器，核对真实骨骼、逐关节有效性和样本时间，再进行录制。系统轻捏可用不能证明应用收到骨骼。环境故障见[追踪排障](TRACKING_TROUBLESHOOTING_ZH.md)。

## 录制：先从一个印开始

以寅为例：

1. 面板的“当前印模板”选择 `Assets/ScriptableObjects/手印识别配置/寅.asset`。
2. “录制标签 / Seal label”填写 `寅`。模板选择和录制标签是两个独立字段，不会自动同步。
3. 设置“准备倒计时”为5秒、“自动录制”为5秒。先点击“准备录制”，在倒计时期间摆好手印；开始提示音响起后保持，结束提示音响起后即可放松，文件已自动保存，不必伸手点停止。若准备时间不够，改成10～15秒。
4. 每次先点击准备，再摆印；换少量位置、朝向、手部间距，录下一次。先收集10～20次独立尝试，作为原型调参的起点，不是准确率保证。准备时锁定本次标签；不需要录制时点“取消准备”。
5. 另录自然放松、相似但错误的姿态及结印过渡，标签分别填 `none`、`near_miss`、`transition`。过渡动作不要整段都贴成正印标签。

不要只录一个动作保持一分钟，再把相邻帧当成大量独立样本。后续训练/测试按不同录制轮次或人员划分，避免同一次动作的相邻帧同时进入训练和测试。

录制是UTF-8 JSONL，每行一个原始双手快照，含时间、标签、关节姿态、版本、手尺寸与有效性/置信度。它不是视频，也不是只保存识别结果。特征和分数会在回放时重新计算。

编辑器录制路径：

`C:/Users/鲁迅/AppData/LocalLow/DefaultCompany/NarutoVR/SealRecordings`

以面板显示路径为准，后续修改Company/Product Name会改变位置。文件名含UTC时间和唯一ID，标签在文件内容中。默认准备5秒、录制5秒，实际录制时长受组件Recording Limit Seconds（默认60秒）限制。到时自动关闭并刷新文件。应用暂停会取消准备/停止录制，因此摘下头显或切换应用后应检查状态。

Quest独立包使用组件上的 `Record On Start`：设置Sample Label、Preparation Seconds、Capture Seconds后保存场景、构建Android APK；启动后倒计时并自动录制保存。数据留在头显的Application.persistentDataPath/SealRecordings，之后拷回电脑回放；当前尚未构建或验证该APK，也没有独立包内的录制按钮。USB连接电脑不等于Unity面板能直接访问Quest独立包的数据。

## 回放与模板标定

1. 停止录制。点击“打开JSONL回放”，选择原始文件。回放不要求连接头显或保持Play。
2. 拖动Frame滑块，找到稳定、正确且相关特征置信度高的帧。Scene视图可查看录制骨骼，面板显示45项连续特征。
3. 选中对应印模板，点击“从当前有效特征生成模板草稿”。这会替换该模板已有规则，并将它标记为未校准；后续手工调参不要反复点击来覆盖修改。
4. 初始草稿只来自当前帧：Min=Max=该帧数值；角度软容差15度，距离软容差0.015；有效且高置信的特征初始权重1。它没有计算多帧平均，也没有从图片推导标准。
5. 回放其他正确尝试，找稳定区间，扩大Min/Max；将与相近印有区分度且追踪稳定的特征提高权重。易被挡住、跳动很大或所有印都相似的特征降低权重，必要时设0。
6. 回放负样本和其他印，观察误通过情况。每次改一组参数，既检查正确动作能否通过，也检查相近错误动作会不会误通过。
7. 完成初步校准后勾选“已确认模板”，按“保存模板修改”。阈值可以在面板调；覆盖率下限和连续达标保持时间在对应SealProfile资产Inspector里调。

| 参数 | 意义 | 调整方法 |
| --- | --- | --- |
| Min / Max | 满分的目标区间 | 由多次真实正确样本确定，避免只卡一个数值 |
| 容差 | 离开目标区间后，分数下降到0的宽度 | 越宽越容易通过，也更可能混淆 |
| 权重 | 此特征对整个印的影响 | 0禁用，较大值强调可区分的稳定特征 |
| 必需 | 此特征不可用时拒绝该印 | 只给少数可靠的锚点，且该规则必须有正权重 |
| Coverage | 可用正权重占总正权重的比例 | 默认至少80%；低值时先查缺失和置信度 |
| Threshold | 总分阈值 | 默认80%；先选对特征，再调阈值 |
| Hold Seconds | 持续达到条件的时间 | 默认70ms；缩短更快，但可能误认过渡 |

默认不接受低置信特征。不要为消除LOW/N/A就全局放宽；优先剔除不可用特征，利用真实采样选择替代特征。若完全不可观测，改权重或模型也不能保证还原隐藏手指。

评分例子（仅说明公式，不是任何印的实际阈值）：目标角度180～200度、容差20度，测到190得1分，210得0.5分，220得0分。总分为加权匹配度除以全部正权重；缺失特征贡献0，其权重仍留在分母，防止少量剩余特征导致虚高。

## 从录制生成范围并实时测试

1. 打开JSONL回放，选定要标定的印模板以及该文件内的正样本标签。
2. 点击“使用该标签整段录制，为某印生成模板草稿”。至少需要10帧双手有效且高置信数据；特征须在至少80%的有效帧中可用，目标范围取10%～90%分位。该操作替换当前模板的规则并保留未确认状态，可撤销。初始权重均为1、角度软容差15度、距离软容差0.015，仍需用其他样本检查混淆情况。
3. 检查草稿，勾选“已确认模板”并保存。初次可以只建立一个印，先验证它与未知动作的区别；判断十二印之间是否能区分，需要逐个建立模板。
4. 点击“实时测试（不录制）”，进入Play并连接Quest，直接摆出手势即可。可以在摆动作前选择预期印；它仅用于显示“正确/不一致”，不会改变识别结果。
5. 面板显示所有印的排名、分数、覆盖率和偏差较大的特征；头显显示最终结果、状态和前三名。没有达标模板时返回未知，两个达标印分差不足5个百分点时显示无法区分，持续保持到时才确认，不强行挑一个印。
6. 退出测试返回采集/调参。测试模式会停止录制且不会修改模板。Quest独立包可在SealLab组件中勾选“测试模式（不录制）”，保存场景后构建。

得分是匹配度，不是模型置信概率或实测准确率。采样率不保证每帧是独立光学测量。当前分位数草稿不自动选择最有区分度的特征或学习权重。

Inspector中的自定义组件、印模板和特征规则已经添加中文Header分组、字段名称及悬停说明。内部序列化变量名保持兼容原场景和模板。

## 常见现象

| 现象 | 优先排查 |
| --- | --- |
| 左右均UNAVAILABLE、全部N/A | Quest系统手追踪、Link连接、Meta活动OpenXR运行时、是否进入Play |
| 单只手/某些手指LOW或N/A | 是否遮挡、离开视野、动作太快；不要先扩大所有容差 |
| 有数值但分数始终0 | 模板是否选对、是否校准、是否有正权重规则、对应特征是否低置信 |
| 正确动作分数高但不识别 | Coverage、必需项、持续时间，以及是否在看实时模式 |
| 回放条显示通过，但没有运行时事件 | 回放面板显示的是单帧评分；运行时WhenSealRecognized另有持续时间判断 |
| 改了当前印模板，录制标签却没变 | 两个字段独立，要手动填写标签 |
| 录制为空 | 是否有新追踪数据；没有头显不会凭空生成骨骼。回放拒绝空文件 |
| 录制有帧数，但全部N/A | 文件保存了追踪状态快照，不代表骨骼有效。先检查connected/tracked及双手置信度；全程未追踪的录制不能用于标定 |
| 突然停止录制 | 是否达到设置的录制时长，或应用因摘头显/失去焦点而暂停 |

## 代码对应关系

- `Assets/scripts/logic/SealLab/SealLab.cs`：从实际IHand获取快照，检查新鲜度，驱动录制和实时识别。
- `HandSnapshot.cs`：原始数据结构，以及供SDK读取冻结快照的IHand包装。
- `SealFeatureExtractor.cs`：调用SDK FingerShapes，追加双手相对几何，输出45项特征。
- `SealProfile.cs`：ScriptableObject模板、参数合法性检查、加权评分。
- `SealRecording.cs`：流式JSONL写入与校验读取。
- `RecordingSchedule.cs`：准备倒计时、定时采集、到时停止；不依赖追踪是否产生新帧。
- `SealLabView.cs`：头显内骨骼线条和数据摘要。
- `Assets/scripts/ui/Editor/SealLab/SealLabWindow.cs`：实时/回放面板、生成草稿、手动调参。

当前保存了12个空模板，不是已经训练完12个印。先用一个印验证“真实数值→录制→回放→草稿→调参→识别”，再扩展其他印。
