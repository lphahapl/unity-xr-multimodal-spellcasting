# 第二章②祭坛首次战斗 · 三敌接线与验收

祭坛首次接敌使用同一个房间，分别登记搬运镇石的残机偶、普通近战残机偶和远程掷火残机各一只。三者均为房间初始敌人。③工坊 F1/F2 两名屋顶预置敌人与院场精英保留各自的房间。

## 生产资产

| 祭坛成员 | 目录 ID | 实际资产和行为 |
|---|---|---|
| 搬运镇石的残机偶 | `stone-carrier` | 与普通残机偶共用 `CanJiOu_Room.prefab`。生成服务按此定义额外挂载 `StoneCarrier`，创建 A4 石体。已有 `StoneCarrierPost` 绑定巡逻点、本轮镇石和 A 篮。 |
| 普通近战残机偶 | `canjiou` | 从 `enemies/canjiou` 加载同一角色 Prefab，按自己的租约与普通近战逻辑运行。该定义的基础生命为 50。 |
| 远程掷火残机 | `zhihuocanji` | 从 `enemies/zhihuocanji` 加载 `ZhiHuoCanJi_Enemy.prefab`。Prefab 配置 Gunplay 及 `ZhiHuoFireCore.prefab`。当前定义和实体均未覆盖战斗数值，因此使用现有基础默认生命 150。 |

三份定义均在本关敌人目录中。交接开始时的正式场景 SHA-256 为 `e7aeb66bbe4f23bd8ff8b209db005a47565c2e4736f6c92625302145fe785cc6`。该快照的祭坛仅登记工奴，工坊另有两只预置和一项精英租约。各敌人 GUID、Addressables 地址、房间列表及依赖散列见[场景与目录基线](source-snapshot.json)。

## 两次新档的清场与镇石

| 击杀顺序 | 第一、第二名阵亡后 | 第三名阵亡后 |
|---|---|---|
| 工奴 → 近战 → 掷火 | 原石已落地。玩家两次提前登篮，均不能施力。 | 清场事件累计一次，登篮后可牵引这块原石。 |
| 掷火 → 近战 → 工奴 | 原石始终随工奴携带，房间仍在战斗。 | 工奴掉下原石，清场事件累计一次，登篮后可牵引。 |

两个新档都在零亡和一亡时退场再进入。每局总共只创建三只，幸存者保留原租约和剩余生命（近战受伤后仍为 49/50）。同一局中石块和刚体的实例 ID 一直相同。本项用正式房间、租约、受击和原 A 篮，桌面驱动玩家位置并提交指定致命命中；结束条件为三亡后登篮开放千钧符。[清场、重入与原始轨迹](Encounter/README.md)

## 行为实测

逐只归因时，探针暂时暂停另外两只。以下结果取自 Unity 6000.3.10f1 Play 的真实 Animator、导航与受击入口。[分项动作断言](Actions/actions.txt) · [四张现场截图与动作轨迹](Actions/README.md)

| 敌人 | 观测 |
|---|---|
| 工奴 | 原搬运剪辑驱动身前 A4 八件网格，54 个连续可读动作帧与持姿相符。沿原路线行走 0.713 m，受到普通伤害后生命从 50 降至 49，撤离时继续持有原石。 |
| 近战 | 在玩家进入视野后追近 2.033 m，距离 1.572 m 时起手。有效窗口内真实玩家收到 8 点伤害，生命从 100 降至 92。 |
| 掷火 | 距玩家 8.062 m 时开始攻击，动画相位 0.555 锁定落点。玩家横移 1.45 m 后预警环保持原位，实际火核以 6 m/s 飞行，连续观测到 5.50 m。随后角色有走位及转向。 |

**三只同时行动。** 在 `a5842a97…` 的正式场景副本中，玩家站在祭坛入口，保持朝向且不闪避。工奴巡逻了 5.501 m，近战实际命中 3 次，掷火残机放出的两枚火核各命中一次。玩家从 100 HP 到倒地共 10.403 秒。该局用于验证同场行为和伤害来源。[同场伤害、火核与轨迹](Encounter/live/assertions.txt)

## 场景作者接入

使用[三敌安装器](SceneHandoff/Chapter02AltarTrioInstaller.cs)补齐既有祭坛房间。将其放入场景作者副本的 Editor 目录，打开二章场景，运行 **Tools → NarutoVR → 第二章断衡悬道 → 补齐祭坛三敌**。核对三项出生登记后，由正式场景作者保存。三种敌人都使用独立地面点，工奴继续引用原背石起始位。已经符合条件的三项登记会保留现有布场。

清场取决于房间持有的全部租约。工奴死亡会掉下原石；有其它祭坛敌人存活时，A 篮继续锁住千钧符。三敌全部阵亡且玩家登篮后才开放牵引。[遭遇判定](../../../../Assets/scripts/logic/Rpg/CombatRoomEncounter.Spawning.cs) · [乘员与镇石门控](../../../../Assets/scripts/logic/Enemies/BallastBasket.cs)

旧单工奴运输探针在击败工奴后直接等待 `room.IsComplete`。复跑三敌版需要先验证单亡未清场，再解决两名守卫，之后继续原千钧符与乘篮测试。[旧 A 篮探针](../Chapter02Assembly/basket-transit-1126/A/Editor/Chapter02BasketAChecks.cs#L159)

初始版和最后锁定的 `a5842a97…` 均通过编辑态回归，各 13 项，覆盖重复执行、撤销重做、保存重开、自定点位与冲突时零改动。最后一版还重跑了两种击杀顺序和三敌同场。正式场景磁盘状态与副本实测分开记录。[安装交接](SceneHandoff/README.md) · [正式场景编成回读](scene-delta.json)

房间运行时随后增加提前显示守敌的选项。使用同一场景快照及新版运行时 `0fb0aa65…` 再跑两种顺序，当前祭坛的该选项为关闭，玩家在接敌线外 2 m 等待时没有活跃租约，跨线后三人正常生成，两轮重入和清场断言再次通过。[新版房间的工奴先死回归](Encounter/preview-default/carrier-first/assertions.txt) · [工奴最后死回归](Encounter/preview-default/carrier-last/assertions.txt)
