# 祭坛退场重入与 A 篮运输

Unity 6000.3.10f1 在二章正式场景快照 `e24e6a26` 的隔离副本运行，从[修桥后存档](postrepair.json)开始。玩家沿实际桥面进入遭遇，再分别于零亡和一亡时步行退出、重新越线。两次退出都解除战斗并拒绝真实命中，重入后幸存者的租约和生命保留。首次线外预展示的镇石与刚体始终保持同一实例。进程以 0 退出。[原始断言](assertions.txt) · [退出码](exit.txt)

| 环节 | 实测 |
| --- | --- |
| 正式房间与出生 | 租约依次为工奴 1、近战 2、掷火 3。玩家越线后激活原先的三只守敌。 |
| 一亡、二亡 | 先击败掷火残机。工奴受击后按正式导航撤向示例落石位置；第二个击败工奴，原石转为动态刚体。两次均未清场，石头无法施符，A 篮未启动。 |
| 三亡与入篮 | 近战最后死亡，清场事件触发一次。玩家沿甲板实步登上 A 篮，取原腰槽实笔，三次绘制自由千钧符。采样经真实匹配器、笔尖命中及刚体受力，最终触发一次锁槽。 |
| 同石运输 | 镇石实例 −6340、刚体 −6336。最终石根到槽心 0.00000 m，槽心上层世界位置 (−9.1214, 80.2450, 21.0000) m。原乘员和原石随 A 篮下降 80 m。玩家走出篮口抵达中层静态存档点，石块仍锁在原槽。 |

这次用桌面输入驱动正式步行的 `WalkStep`、手部观察样本和原自由画板，指定击杀顺序时通过 `EnemyObj.ReceiveHit` 提交命中。第二次运行中所有玩家脚位移动均经过生产步行或升降篮移动。没有运行中的 XR 显示子系统或活动硬件 Loader。私有 XR 配置在退出后恢复到原来的 SHA-256。[牵引过程](pulls.csv) · [隔离与恢复](isolation.json)

第一轮沿用旧探针的固定抬笔角度，第三次牵引时原石越过槽口，与下一步待用的玩家位置重叠，停在离槽 0.799 m 处。每三步记录一次的轨迹中，该次最近读数为 0.690 m，正式捕获半径为 0.65 m。终测的桌面操作者在石头抵达篮门后以较低笔尖沿槽心缩短回拉，第三次牵引成功锁槽。两次运行均沿用正式碰撞、捕获半径、刚体和符力配置。
